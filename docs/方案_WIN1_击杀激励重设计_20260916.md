## §0 背景与归因结论（09-16 零干扰核查）

**问题**：主日志最后一条 `[TOWN_CAPTURE]` 停在 L89715（step 695056，72_01，hero-kill proxy），此后跨越 4 个 run 段 0 触发，与 09-15 #231 空帧假报修复（commit 5c2f2b8，双帧确认，step 695099 上线）时间线重合。存在两种假设：①修复消除假阳性后暴露真实占城能力缺口；②双帧确认过严把真击杀也挡了。

**核查证据链**（三层，均指向①）：

1. **修复前 100% 假阳性**：commit 5c2f2b8 实勘 —— 全历史 218/218 TOWN_CAPTURE 经 battle_quality_events.log 严格战斗配对 100% 为空拍误报。L89715（step 695056）恰为修复上线（695099）前最后一次误报，归零起点与上线严格对齐。
2. **修复后连单拍差集痕迹都是 0**（决定性）：battle_quality_events.log（持久 append-only，834 行）中全部 9 条 `[BHERO_KILL]` observe-only 打点集中在文件头部 L1-9 且**全部 `live_slots=0`** —— 按修复后打点条件 `if _bnow:`（非空拍才打点，ep_runner_one.py L1049-1056），这 9 条只能是修复前旧代码空拍期打的。修复后：0 条非空拍 BHERO_KILL、0 条 "confirmed 2 frames" 发奖。即蓝英雄集合从未在任何非空拍消失过哪怕一个，双帧确认从未收到过需要裁决的挂账。
3. **防误报机制工作正常**：修复后 HEROSEG_EMPTY 空拍仍持续出现（文件尾部多条，含 72_01 / 72_02_duel / 108_02_duel）均被正确冻结，无一误发。

**残余不确定性**（如实登记）：
- 唯一理论盲区："击杀恰好发生在 ep 最后一个非空拍"（无第二拍完成确认与打点）。BHERO_KILL 在击杀后第一个非空拍即留痕，4 段几十局一条都没有，概率上不成立；批次 B 的逐 id 发奖设计天然不封死此盲区（若发生会在终局留 pending），如需彻底封死可在 ep 终局处加 `[KILL_PENDING_EXPIRED]` observe-only 打点（需停训窗，非必需）。
- /tmp/hermes_ep_*.log 明细仅剩 5 个（轮转），无法逐局复核；但旁路持久日志覆盖全程，不影响判定。

**结论**：**"没杀到"（真实能力缺口），不是"杀到没认"（proxy bug）**。历史 218 次 capture 基线全部为假，当前"0"才是真实基线。WIN-1 判据①需按"从零建击杀能力"重做达成手段。

**旁证**：本窗（09-15 修复后）12 次 `[GUARD] won` 全部落在 King_of_Pain（H3M 组 6/10=60%）；72_01/72_02/108_02 avg_r=+49.8 但 0 打守卫、0 击杀、0 占城，正奖励全靠探索/经济 shaping 支撑。

## §2 行为链分解与激励映射

```
接近蓝英雄 → 首次接战 → 击杀(×3) → 全歼 → 占城
  P-H1         P-H2      P-H3阶梯   proxy+100(已修,不动)  capture reward+100(已有,不动)
```

- **终点奖励全部保持不动**：hero-kill proxy +100（双帧确认）、owner 1→0 capture reward +100。
- 本方案只补中间梯度，不改判据① 定义（TOWN_CAPTURE 非零，修复后重新计）。

## §3 批次 A：蓝英雄接近梯度（P-H1，先上，风险最低）

| 项 | 设计 |
|----|------|
| 状态源 | obs heroes 段（与 `_bnow` 同源解析），**非空拍才更新，空拍冻结** |
| 计算方式 | 我方英雄到最近蓝英雄距离，**新低制**：`r += 0.2 × max(0, prev_min_d − cur_d)`；远离不扣（防往返走位刷分，复用守卫接近梯度 P3 成熟模式） |
| 每局上限 | cap +25（72 图红→蓝曼哈顿 ~128 格，满贯 ≈ +20~25，量级对齐 RECRUIT/BUILD 单窗收益） |
| 参数化 | `--blue_hero_grad`（默认 **0** = 关闭）+ `--blue_hero_grad_cap`（默认 0 = 不限）；合码零干扰，开窗只改 systemd 启动参数 |

## §5 防 hacking 专项（逐条对冲历史踩坑）

1. **空拍冻结**：全部新奖励继承 `_bnow` 非空前提（#231 机制直接复用）。
2. **双帧确认**：击杀奖只在挂账后下一非空拍仍缺席才发，瞬态撤账（改逐 id 粒度，机制不变）。
3. **新低制 + cap**：接近梯度无法靠往返走位刷分。
4. **接战幂等**：battleStarted 事件每局每敌英雄一次，无法反复触发。
5. **步罚 -0.1 保持 + death_penalty -50 保持**：送死换 +15 接战奖净亏，天然抑制自杀式接战。
6. **TOWNSTALL / 状态级与动作级循环罚保持**：防"向蓝英雄方向卡墙刷新低"。
