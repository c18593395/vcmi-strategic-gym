### 1.2 真正的闸门: 观测 passable 通道 (这就是"真实击杀=0"的最终机械根因)

- obs[3211:3219] passable 通道把**敌英雄格标 0** (知识库"贴脸"口径) → 三重封锁:
  1. 模型方向动作: ep_runner L478-481 `logits[:8][~passable]=-inf` → 踏向敌格的方向永不被采样
  2. MOVE_TO/BFS: passable=0 不入 BFS → 引导只到邻格
  3. 蓝方 AI: AAI.cpp:109-111 nearestInteractable **显式跳过 HERO** 且不选敌占对象 → 蓝英雄不会主动进攻; 唯一战斗通道 = 蓝 AI 目标格恰被红英雄占据的"间接撞上" (概率极低且不可控)
- 结论: **模型/引导/对手三方全部结构性无法踏入敌英雄格 → 真实战斗 (含攻城战, 城格同样 pas=0) 在当前观测下永不可触发** → WIN-1 "真实击杀=0"、TOWN_CAPTURE=0、批次B 判据②③ 恒 0, 全部由此闭环解释
- 战斗内层再核过: BAI 主动投降评估 `#ifndef ENABLE_ML` 被编译排除 (BAI.cpp:380-389), mlbot 需 GRAIL 不触发; 唯一逃走通道 = v13 模型 RETREAT 动作 (野战默认可 flee) — 不影响"是否开战"
