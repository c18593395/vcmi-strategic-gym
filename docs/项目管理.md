**改动流向铁律（09-26 用户拍板）**：所有代码/配置/补丁/引擎改动必须在本地仓完成并 commit，再同步到服务器 172.16.2.40；**禁止在服务器侧直接改源树**。WSL 与服务器两侧产物保持同步（防 09-24「双产线漂移」复发）。
同步机制：① C++/多文件 = 本地 commit → `git format-patch` 整包 → scp → 服务器 `git apply --check` 后 apply（带 `.bak` 备份 + rollback 垫）；② 单文件 = 本地改 + commit → scp；③ 知识库/踩坑点文档 = 服务器改完 scp 回本地再 commit；④ 回连/动手前先核两侧 diff（`.so`/runner/pool_index/model 一致性）。
例外登记：部署面 env 覆盖（systemd unit `Environment=` 等）不算改源树；服务器上**只读**诊断 + `.bak` 备份不违反本条。

## 二、编号规则（AI 必读）

- **T 系列**：大项 `T1`~`T14`，子任务 `T.n`（如 T6.2）；插入中间任务用小数（T6.5）。对应 `总任务.md`。
- **P 系列**：当前与紧急任务，独立流水号 `P-001` 起步（两位补零），**优先级（P0-P3）是字段不是编号**，降级/升级不改编号。对应 `当前任务清单.md`。
- **编号不复用**：任务取消/合并保留原号打 ❌ 注明去向，避免引用断裂。新增大项顺延 T15+。
- **最小任务单位**：可独立执行、有自己判据（怎么算完）/回退线的动作单元。
- **部分完成自动拆分（09-27 用户拍板）**：任务收口时若"已验证完成一块 + 剩余不能一次完成"，父任务标 ✅ 注明拆分去向并归档，剩余自动开子任务号：
  - T 系列：`T14.4A / T14.4B / T14.4C`；再拆 → `T14.4A1 / T14.4A2`，最多两层（字母后数字），不再嵌套字母。
  - P 系列：不搞后缀层级，新开流水号，描述首行注明"承 P-0xx 剩余"。
  - 拆分门槛：剩余是可独立执行的动作单元（有判据/回退线）才拆号；仅一句"待顺带观察"的挂在父任务详情"遗留"行，不拆。
  - 父任务拆分后**必须收口**，禁止继续以"部分完成"挂活跃区。
- **非任务编号**（保留原名，大量历史引用）：`WIN-x`（已废除新编号，存量映射见当前清单）、`S-x`（服务器基建，已完成的归档留原名）、`OBS-x`（长期观察项）、`R-x`（风险登记）、踩坑 `#n` / fact_store `#n`（知识库引用锚，永不动）。
- **状态标记（仅四种，09-27 用户拍板，禁用其他符号）**：✅ 已完成 ｜ 🔄 进行中（含观察中、含部分子项完成的大项）｜ ⬜ 未开始（含等触发，触发条件写入描述）｜ ❌ 取消/终止（保留原号注明去向）。~~🟡 🔶 ⏹ 废除~~。

## 三、长期纪律（历史拍板固化）

1. **错窗纪律**：激励轴 / 地图轴 / 难度轴 / 晋级与开经济**不同窗**，一次只加一个难度轴。
2. **竞态类验证纪律（09-23 血泪，置顶）**：任何"概率性/竞态类问题已修复"的结论，必须 **N≥4 重复 + 基线对照**，单样本通过不算数；记**逐图复现率**而非过/不过；崩溃栈 gdb 下不复现不能反证没问题；改源码重编必须确认构建日志出现 `Building CXX object`（`shutil.copy2` 保留旧 mtime 会让重编变空操作）。工具：`py/_298_repeat.sh` / `py/_298_crash_gdb.sh`。
3. **OBS(3464) / 动作空间冻结**：禁增删维度；扩展只走预留位或旁路（terrain 走 terrain_grid.bin）。
4. **VCMI 铁律**：不重编 libvcmi.so 引擎本体（新 AI 模块走独立 .so / MMAI plugin 范式）；vcmi-native 与 vcmi-native-build 双目录甄别（生产树 = `/home/administrator/vcmi-native`，构建目录 `rel/`）；`.so` 多副本部署改后同步全部副本。
5. **训练地图 = VMAP**（T01-T06 课程体系）；H3M 已停用（h3m_tool.py 逆向参考）。
6. **改图后必跑同步**：权威源 `maps/training/`，运行时 `vcmi/data/Maps`；改/生成任何 .vmap 后必跑 `py/sync_maps_to_runtime.py --strict`（`--check` 只校验，rc≠0 禁训）。
7. **改 Python 后清 `__pycache__`**；动构建树前备份 .so + 源码。
8. **事实核查原则**："X 是否在用/生效"以**代码 + 运行日志 + 二进制产物**为准，文档仅作索引（防文档过时误判）。训练主日志 `train_loop.log`；运行时 .so 检查 `strings <so> | grep -c <符号>`；Windows vcmi/ 子模块与 WSL vcmi-native 源码可能不同步，源码级改动前先在 WSL 侧 grep。
9. **晋级纪律**：晋级与开经济不同时做。

## 四、日常 SOP

### 4.1 每次会话开始（开机后）

```powershell
# ① keepalive 判活（幂等，计数 ≥1 即正常；重启 WSL/Windows 后必丢失需重拉）
(Get-CimInstance Win32_Process -Filter "Name='wsl.exe'" | Where-Object { $_.CommandLine -like '*sleep*infinity*' }).Count
# 为 0 时拉起：
Start-Process wsl.exe -ArgumentList '-d','Ubuntu','sleep','infinity' -WindowStyle Hidden
# ② 训练状态确认（当前常态 = 服务器训练）
ssh / wsl: systemctl is-active homm3-train-server   # 服务器 N=16，日志 train_full.log
# WSL 回切态才看：systemctl is-active homm3-train-v5（存活性以 PID etime + 日志 mtime 为准，踩坑 #201）
```
- keepalive 作用域：WSL 侧有常驻任务（Track2 / 回切训练）时必拉；纯服务器训练且 WSL 无常驻任务时可省，但判活幂等无害。
- **禁用 `systemctl --user`**（无 user unit，会误报）。

### 4.2 关机前

1. 优雅停训：训练在 WSL → `wsl -u root systemctl stop homm3-train-v5`；在服务器 → 服务器侧 stop。确认日志出现存档行（`Saved STATE_PATH (step=N)`）。
2. 确认 unit 保持 enabled（WSL 冷启动自动续训兜底）；确认无残留引擎进程。
3. 主仓 `git status` 干净（未提交工作要么 commit 要么登记到任务清单）。

### 4.3 训练启停（含改代码后）

- 停：`wsl -u root systemctl stop homm3-train-v5`（root 免密通道；普通用户需 sudo 密码）→ 优雅保存 checkpoint。
- 启：`wsl -u root systemctl start homm3-train-v5`（checkpoint resume）→ **立即拉 keepalive**（否则 ~60s WSL idle shutdown 杀训练，09-18 实证）。
- 或一键：`sudo bash py/restart_train_v5_sys.sh`。
- 服务器侧：unit `homm3-train-server`（N=16，enabled，日志 `train_full.log`，监控 `pgrep -c ep_runner_one.py`≈16）。
- 改代码 → 停 → 改 → 清 `__pycache__` → 启 → 拉活。改 unit 双副本（`/etc/systemd/system/` 与 `py/homm3-train-v5.service` 仓内副本）**必须同步改并逐字核对**（踩坑 #306）。
- 训练在跑时的红线：不写运行时 .so / 日志 / GPU 抢占 / eval 抢 CPU；奖励面/引擎面改动不混入在跑窗。

### 4.4 服务器→WSL 回切（服务器挂时，SOP 已固化）

一键 `py/restore_train_to_wsl.sh` 6 步（拉 state → torch 验证 → 前置 unit enabled / XDG Maps / 课程图 → keepalive 提示 → 清 pycache → systemctl start）。要点：续训用 `wsl2_model_state.pt`（含 model+optimizer+step），**纯 ckpt 不含 optimizer 不续训**（踩坑 #328）；服务器恢复在跑时勿双启；只丢最后一轮 PPO buffer（~4-16 局）。

## 五、git 规范

- 「平时说的 git」= 本地仓 `D:\Bigdata\hero3_fresh`（真相源）。
- commit 纪律：只 add 自己改的文件（多 agent/多会话并行时他人的 M 态活文件不带入，S-8④ 约定）；不 commit 密钥/.env/权重/地图二进制；改动前面先 `git status` + `git diff` 核对。
- unit / 双副本类配置：仓内副本与部署副本同 commit、同核对。
- 服务器部署走 §1 改动流向（format-patch / 单文件 scp），服务器侧不再单独产生新代码；回连后 md5 双侧核对。
- push GitHub 前敏感扫描（API key/权重/地图零命中才推）；开源仓路径环境化已done（09-23）。

## 六、多 agent / 多会话协作

- 任务分派：`docs/程序员B工作任务清单.md` / `docs/程序员C工作任务清单.md`（子 agent 各自领取）。
- 合并约定：① 各会话**只 commit 自己名下文件**；② 合并前 `git status` 核对他人 M 态活文件不混入；③ 双副本（unit / .so / 双树）改动合并时逐字核对；④ 子 agent 产出的部署补丁固化为独立 patch 件入 `py/`，服务器侧不产新代码；⑤ 交叉改动（同一文件两会话都改）→ 后者 rebase 前者，冲突上报用户拍板。
- 子 agent 调用后：结果回写任务清单对应编号，完成的按拆分规则销项/拆号。
