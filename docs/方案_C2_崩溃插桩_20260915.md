**规律**：运行期训练崩溃几乎都是「引擎/AI 断言（SIGABRT，有文本栈）」或「空指针（SIGSEGV，无文本栈）」；地图数据类已被 09-14 三道拦截 + sync 预检挡在训练前；纯随机内存腐败型至今**无实证**。

## 2. 现有证据链与缺口

**在位设施**
- ep_runner 独立子进程；vcmiserver = `rel/bin/vcmiserver` 独立二进制（connector .so fork/exec，配 `libmlserverplugin.so`）。
- ep 全量 stdout/stderr → `/tmp/hermes_ep_<ppid>.log`；主进程按词表转储（含 `Assertion`/`[ERROR]`/`[ZOMBIE]` 等，train_wsl2_ppo_v2.py L214-221）。
- 09-14 三道拦截：rc≠0 / traj 身份不符 / obs_nz=0 → 丢弃不入 buffer，主日志 `[FILTER] ... rc=N`。
- 局看门狗：`STEPS_PER_EP*60+300=12300s` 超时 kill（R7 query 另有 300s fuse）。
- gdb / addr2line 已安装；addr2line 流程在 PHASE_A_SEGFAULT_REPORT.md §八。

**四个缺口**
1. **rc 只有裸数字**：-11/-6/-15 不翻译信号名（-15 还是 -11 要人脑换），无崩溃计数面板。
2. **ep_log 逐局覆盖**：崩溃局若输出未命中 highlight 词表（典型 = 纯 SIGSEGV 无 VCMI fatal 文本），现场在下一局被冲掉，只剩 rc。
3. **core 不可用**：`/proc/sys/kernel/core_pattern = |/wsl-capture-crash ...`（WSL 管道接管）、`ulimit -c=0`，无 core 文件可 gdb。
4. **fprintf(stderr) 在 MMAI server 内不可见**（#134：console 重定向），C++ 侧临时 fprintf 插桩默认丢，必须带 fflush + 明确 fd。

## 3. 插桩方案（三级，按侵入度，默认只做 L0）

### L0 — 零重编、Python 侧（随自然重启窗，改动最小）

a. **rc 信号名翻译**（train_wsl2_ppo_v2.py L234-236）：
```python
import signal as _sig
_sn = {-(int(v)): v for v in dir(_sig) if v.startswith("SIG") if isinstance(getattr(_sig, v), int)}
name = _sn.get(ep_rc, f"rc={ep_rc}")
print(f"  [FILTER] ep 子进程非正常退出 {name}, 丢弃 ... map={mapname}", flush=True)
```
b. **崩溃局 ep_log 归档不覆盖**：rc≠0 时把 `/tmp/hermes_ep_<ppid>.log` 复制到
`/mnt/d/Bigdata/hero3_fresh/crashlog/ep_{map}_{step:07d}_{ts}.log`（带 map/gstep 名），
保留崩溃前后全量文本；crashlog/ 加 .gitignore。
c. **词表补纯崩溃关键词**：`Segmentation fault`、`core dumped`、`Disaster happened`、
`terminate called`、`AddressSanitizer`（L214 highlights），让无方括号的崩溃行进主日志。
d. **崩溃计数监控**：health monitor 加一条 grep 规则——`[FILTER].*(SIGSEGV|SIGABRT)` 近 100 局 ≥3 次即告警（阈值防单次地图脏数据噪声）。

> L0 改动只碰 train 脚本（不碰 .so/铁律），与 D3 补丁同属"自然重启窗"批次，可合并一次停启。

### L1 — core/gdb 取证（复发时临时开，不改二进制）

```bash
# 选项 1: 解禁 core (wsl -u root, 全局可逆; pipe 被覆盖, 排查完恢复)
echo '/tmp/core.%p.%e' | sudo tee /proc/sys/kernel/core_pattern
ulimit -c unlimited          # 写进 homm3-train-v5 unit 的 ExecStart 前/或 drop-in
# 复现后: gdb rel/bin/vcmiserver /tmp/core.<pid>.vcmiserver -ex "bt 30" -ex "thread apply all bt 10"

# 选项 2: 不碰 core_pattern, gdb 直接包裹 server (需定位 exec 点后包一层 PATH 替身)
# 复发窗口用 gdb -batch -ex run -ex bt 跑训练, 崩溃自动出栈; 性能损失大, 仅短时
```
- addr2line 无 gdb 时的退路：`dmesg` 取 `libvcmi.so[base+off]` → `addr2line -f -C -e rel/bin/libvcmi.so <off>`（Phase A 同款）。
- 注意 vcmiserver 在 connector .so 内 fork/exec，PATH 替身法需先 `ps -ef --forest` 在跑局瞬间确认子进程链（进程短命，可 `while true; do pgrep -af vcmiserver; sleep 0.5; done`）。
- **恢复**：`echo '|/wsl-capture-crash %t %E %p %s' | sudo tee /proc/sys/kernel/core_pattern` + 删 drop-in。

### L2 — C++ 重编插桩（最后手段，走 .so 铁律）

仅在 L1 证实为我方 .so（libmlclient/libmlserverplugin/libMMAI）内空指针、且无断言文本时启用：
1. 备份全部 .so 副本 + 源码（vcmi-native 与 vcmi-native-build 双树）。
2. 在 MLClient init/start_vcmi 与 ML 每步入口装 **信号处理门**：
   `signal(SIGSEGV/SIGABRT)` → `backtrace_symbols_fd(30, STDERR_FILENO)` + `fflush` + `_exit(139)`；
   记住：#134 教训，stderr 在 server 内被重定向，改写到显式 open 的 `/tmp/vcmi_crash_<pid>.txt`（O_APPEND，绕过 console 重定向）。
3. 关键解引用点（fill_v3_fields / target_list / getObjInstance 返回值）加 `fprintf(fd,...)+fflush(fd)` 路径面包屑。
4. 只动 ML 自有文件，不碰 libvcmi 引擎逻辑；重编后多副本同步部署。
5. 回滚 = 恢复备份 .so，无需重编。

## 4. 复发处置 SOP（决策树）

```
[FILTER] rc!=0 出现
 ├─ 单张图/单次 → 先按地图数据类查 (sync --strict / inspect / header), 不动训练
 ├─ 同图反复 rc=-6 (SIGABRT) 且日志有 Assertion → 断言类: grep 断言符号定位,
 │   走 libMMAI/.so 单点重编 (#115 套路), 备份+双树同步
 ├─ rc=-11 (SIGSEGV) 无文本 → L0 归档已开? → 翻 crashlog/ 全量文本
 │     仍无线索 → 开 L1 core 复现 → addr2line/gdb 定位
 │         栈在 ML 自有 .so → L2; 栈在 libvcmi 引擎 → 评估上游/规避, 不死磕 (#105 教训)
 └─ 近 100 局 ≥3 次崩溃 → 暂停晋级/改图, 按上面对类处置, 期间训练继续跑旧图池
```
