## 一、项目概述与当前架构

**目标**：AI 完整操控 HoMM3 真实游戏，战胜玩家（1v7）。

**策略**：VCMI 沙盒训练战略模型 → 真实游戏内存操控 → 自对弈持续进化。

**当前阶段（已核实）**：
- 训练端：WSL2（x86, RTX3060），`py/train_wsl2_ppo_v2.py` 24/7 运行，SIGTERM/SIGINT 安全落盘【来源：train_wsl2_ppo_v2.py L504-505】。
- 模型：自研 PPO `Net`，观测 3464 维状态向量 + 独立 4×21×21 地形栅格，动作 25【来源：strategic_env.py L213-216；train_wsl2_ppo_v2.py L136-151】。
- checkpoint：每 50 step 存 `checkpoints/wsl2_ckpt_<step>.pt`【来源：train_wsl2_ppo_v2.py L660-665】。

**双轨**：
- Track 1 训练（WSL2 GPU）：持续提升模型强度，后台 24/7。
- Track 2 真实游戏对齐（Windows 内存读取）：模型落地真实 HoMM3，内存偏移见 `对齐清单_CN31.md` / `对齐清单_HD.md`。

**服务器 172.16.2.40 角色**：模型仓库（`/models/load`）+ WIN RATE 结果中枢（:8088）+ 旧 SB3 推理服务（:8080）；**不跑新模型训练/评测**（无 GPU + ARM64 旧架构维度不兼容）。详见 §五。

## 二、训练架构（WSL2，逐条核实）

### 2.1 模型 Net
【来源：train_wsl2_ppo_v2.py L136-151】
- 状态分支：`Linear(3464,128) → ReLU → Linear(128,128) → ReLU`
- 地形分支（CNN）：输入 `(4,21,21)` → `Conv2d(4,16,3,padding=1)→ReLU→MaxPool2d(2)` → `Conv2d(16,32,3,p1)→ReLU→MaxPool2d(2)` → `Conv2d(32,64,3,p1)→ReLU` → `Flatten(1600) → Linear(1600,128)→ReLU`
- 合并：`Linear(256,128)→ReLU`（状态 128 + 地形 128）
- 头：actor `Linear(128,25)` / critic `Linear(128,1)`
- `forward(x, terrain=None)`：地形栅格是**独立第二输入**，不并入 obs。

### 2.2 观测空间（OBS_DIM = 3464）
【来源：strategic_env.py L213-216, L285-304】
- obs 是 3464 维**状态向量**；地形以独立 `(4,21,21)` 栅格作为 CNN 第二输入（不在 obs 内）【来源：strategic_env.py L235-236 TERRAIN_GRID_SIZE/CHANNELS；调用 `model(obs, terrain)`】。
- obs 布局（索引，区间总和验算 = 3464）：
  - `[0:8]` global：day/week/month/current_player/map_w/map_h/has_underground/player_count
  - `[8:128]` players（8×15）
  - `[128:336]` heroes（8×26）
  - `[336:480]` towns（8×18）
  - `[480:1155]` local window（15×15×3：可通行 / 对象类型 / 守卫战力）
  - `[1155:3203]` explored（32×32×2）
  - `[3203:3211]` active_hero
  - `[3211:3219]` passable（8 方向，动作屏蔽用）
  - `[3219:3251]` nav（32）
  - `[3251:3315]` target_list（64）
  - `[3322:3326]` enemy_threat（7）
  - `[3326:3330]` battle_pred（4）
  - `[3330:3464]` events(4) + reserved(130)
- 注：区间已逐段相加验证为 3464；`_test_suite M6` 曾误写 3456，已校正【来源：strategic_env.py L287 注释】。

### 2.3 动作空间（25）
【来源：strategic_env.py L186-213】
- 0-7：`MOVE` 八方向
- 8：`INTERACT` 拾取/对话/攻击
- 9：`NEXT_HERO` 切到下一英雄
- **10：`END_TURN` 结束回合** ← 注意：结束回合是动作 10，**不是 24**
- 11：`SPLIT_1OF3` / 12：`SPLIT_1OF2` / 13：`SPLIT_ALL` / 14：`MERGE_FROM` / 15：`SWAP_ARMY`（分/合/换兵力）
- 16-18：`RECRUIT_1/2/3`（最近己方城镇招兵）
- 19-21：`BUILD_1/2/3`（最近己方城镇建造）
- 22：`GARRISON` 驻守 / 23：`RECRUIT_HERO` 招募英雄
- **24：`MOVE_TO` 高层移动：走到最近可交互对象** ← 注意：动作 24 是 MOVE_TO，**不是结束回合**

### 2.4 动作屏蔽（训练真源 ep_runner_one.py）
【来源：ep_runner_one.py L554-575】
- 0-7：受 `obs[3211:3219]` passability 约束（非法方向 `logits=-inf`）
- 8 `INTERACT` / 9 `NEXT_HERO` / 11-15：永久屏蔽（vcmi-native-build 无对应执行分支，纯 NOOP 刷步）
- 16-21（RECRUIT/BUILD）：仅 `T04` 地图开启；非 T04 全屏蔽；开启时还需 `recruit_mask`（`obs[640:672]`，256-bit 位域）与 `build_mask`（`obs[672:704]`，256-bit 位域）位域合法才允许
- 22 `GARRISON` / 23 `RECRUIT_HERO`：永久屏蔽（需双目标/多英雄槽）
- 10 `END_TURN` / 24 `MOVE_TO`：始终可用
- **评测器 `py/winrate_eval.py` 的 `masked_argmax` 必须镜像上述逻辑**，否则评测分布失真。

### 2.5 地图（关键纠正：当前战略训练用 .vmap，不用 H3M）
【来源：train_wsl2_ppo_v2.py L30-95；`maps/training/` 目录；strategic_env.py L491-535】
- **当前战略 PPO 训练统一使用 `.vmap` 冒险地图**，位于 `maps/training/`（该目录实际 68 个 `.vmap` 文件）。
- 训练清单 `MAPS`（train_wsl2_ppo_v2.py）：`T05_adventure_36X36_01.vmap`、`T05_adventure_52X52_01.vmap`、`T05_adventure_52X52_02.vmap`、`T06_adventure_72X72_01_duel.vmap`、`T06_adventure_72X72_01.vmap`、`T06_adventure_72X72_02_duel.vmap`、`T06_adventure_72X72_02.vmap`、`King_of_Pain_h3m.vmap` 等。
- `King_of_Pain_h3m.vmap` 实为 `.vmap` 文件，仅文件名加 `_h3m` 后缀以通过 `strategic_env.py` 的 assert（要求 mapname 含 `s1`/`mini`/`adventure`/`h3m`）【来源：train_wsl2_ppo_v2.py L75 注释】。
- `strategic_env.py` 默认地图 `adventure-A1.vmap`，assert 要求 mapname 含 `adventure` 等关键字【来源：strategic_env.py L491-535】。
- **H3M 经典图（`available_maps.json` 110 张、`scan_maps.py` 扫描 `.h3m`）是另一套**——用于旧项目 ELO / 经典图评估，不是当前 PPO 训练图集。二者不可混淆。

### 2.6 Checkpoint 与对手池
【来源：train_wsl2_ppo_v2.py L656-685, L29, L107-108】
- 每 50 step：`checkpoints/wsl2_ckpt_<step>.pt`（仅权重）+ 同时存完整状态 `wsl2_model_state.pt`（含优化器+step）。
- best_vloss 时额外存 `wsl2_model.pt`（权重，供对手池/推理）。
- 保留最近 `OPPONENT_POOL_SIZE=10` 个 `wsl2_ckpt`，旧文件自动删除。

### 2.7 胜负口径
【来源：strategic_env.py L174-176, L1075-1149】
- `state.game_over == 1` → 红方（RL）胜；`== 2` → 蓝方胜。
- `winrate_eval.py` 用 `info.get("game_over",0)` 统计；`game_over=0` 记为 DRAW（不计入胜率分子）。

## 三、环境构建（WSL2，当前）

### 3.1 三件套同源编译
- vcmi-native 三件套（libvcmi.so + libmlclient.so + connector）必须同源编译，否则 ABI 不兼容崩溃【来源：服务器踩坑点.md 1.3】。
- 启用开关：`-DENABLE_ML=ON -DENABLE_MMAI=ON -DENABLE_NULLKILLER2_AI=ON`（历史沿用，待 WSL 侧复核）。
- 环境变量：`LD_LIBRARY_PATH=.../vcmi-native/rel/bin:~/vcmi-workspace/vcmi_gym/connectors/rel`、`STRATEGIC_STATE_LIB=.../libmlclient.so`。

### 3.2 启动训练
```bash
MSYS_NO_PATHCONV=1 wsl -d Ubuntu -- bash /mnt/d/Bigdata/hero3_fresh/train_loop.sh 2>&1 &
bash /mnt/d/Bigdata/hero3_fresh/check_training.sh   # 查状态
```
> 注：本机 WorkBuddy sandbox 禁用 `wsl.exe`，以上 WSL 侧命令需用户在 WSL 内执行【来源：服务器踩坑点.md 2.2】。

## 五、服务器 172.16.2.40（实测 2026-09-24，live）

> 登录：`ssh root@172.16.2.40`（Windows 侧免密）。所有端口局域网可达（防火墙 ACCEPT）。

### 5.1 硬件/环境（实测）
- CPU 鲲鹏 920 ×2，64 核 2.6GHz（ARM64/aarch64）；内存 250GiB；`/DATA` 25.5T（LVM）。
- 无 GPU；torch 2.13.0+cu130 仅 CPU 运行。
- OS openEuler 24.03 LTS-SP3；Python 3.11.6（/usr/local/bin/python3）。
- 已装 torch / onnxruntime / fastapi+uvicorn / SB3 2.9.0 / docker / Xvfb :99。
- 现存 `/DATA/hero3`（旧训练项目：80+ SB3 模型 + vcmi-build/bin 全套 .so）、`/opt/vcmi`。

### 5.2 推理服务 :8080（SB3 旧架构，实测在线）
【来源：curl http://172.16.2.40:8080/health → `{"status":"ok","models_loaded":80,"current_model":"ppo_Key to Victory_h3m_500000steps"}`】
- 代码 `/DATA/hero3/inference_service.py`；systemd `vcmi-inference`（active）。
- 扫描加载 `/DATA/hero3/models`（~80 SB3 zip）、`vcmi-build/bin/models`、`vcmi/`。
- API：`GET /health` / `GET /models` / `POST /models/load` / `POST /models/{name}/activate` / `POST /predict`。
- **只支持旧 256 维 SB3 模型 predict**；新 3464 维 ONNX 能 load 但 predict 维度不兼容。

### 5.3 WIN RATE 结果中枢 :8088（新，实测在线）
【来源：curl http://172.16.2.40:8088/health → `{"status":"ok","count":0}`】
- 代码 `/DATA/hero3/results_hub.py`；systemd `vcmi-results`。
- 接收/查询历史 WIN RATE，落盘 `/DATA/hero3/output/winrate_history.jsonl`，进程重启自恢复。
- API：`GET /health` / `POST /results` / `GET /results` / `GET /results/latest` / `GET /results/{model}` / `GET /models`。

### 5.4 checkpoint 自动推送链路（新）
【来源：docs/checkpoint推送链路与WINRATE自动评测.md】
- 关键约束：服务器 ARM64 旧架构跑不了新模型（3464 维），WIN RATE 必须在 WSL2 算。
- 链路：WSL2 训练存档 → `ckpt_push_hook.py`（导出 ONNX → scp → `/models/load`+activate → 本地 `winrate_eval` → 结果 POST :8088 + scp 落盘）。
- 触发：`ckpt_watcher.sh`（cron 每 15min）或训练脚本尾部 hook（`Popen`，不阻塞训练）。
- 查结果：`curl http://172.16.2.40:8088/results/latest`。

### 5.5 服务器定位结论
- **适合**：并行评测（64 核）、ONNX/SB3 推理、CI 构建、checkpoint 仓库（25T）。
- **不适合**：RL 训练本体（无 GPU）、新模型评测（ARM64 旧架构维度不兼容）。
- 与 WSL2 RTX3060 训练互补：训练留 WSL2，评测/推理/CI 卸载到服务器。
