# 动作空间设计文档 v2 — 全量冻结版 (长期项目宪法)

> 日期: 2026-08-14
> 依据: docs/源码分析地图.md (9 面源码枚举, CCallback 全集 + CGameInfoCallback 全集)
> 定位: 长期项目宪法。动作空间与 OBS schema **一次设计到位并冻结**, 以后只允许:
>   - 启用预留动作码 (obs 不动, 权重不废)
>   - 填充预留 obs 段 (维度不变, 权重不废)
> 禁止: 新增维度、改动既有字段语义、推翻参数化结构。
> 目标: 1v7 高级电脑 → 2-3 真人 → 终极: 人vs人vs模型联网 (VCMI Windows 引擎内部接口)

---

## 0. 设计原则 (为什么这样不会返工)

1. **动作空间 = CCallback 公开方法的封闭子集**。50+ 方法全部枚举, 按需分配动作码, 其余进预留。引擎没有的方法不存在于动作空间, 不会"训到一半发现缺"
2. **OBS = CGameInfoCallback/CGameState 可读状态的封闭子集**。全部字段枚举, 现在能读的进 schema, 以后才能读的**占位预留**(维度固定)
3. **动作码预留 + obs 段预留双保险**: 新增能力只启用预留位, 输入输出维度不变, 已训权重永不作废
4. **参数化结构**: 动作 = (verb × target × param) 三维, 天然支持"分兵给谁""招什么兵"这类组合, 不需要为每个组合发明新码
5. **每个字段/动作有源码出处**: 文档所有条目标注文件+方法, 实现时照抄 NK2 现成调用

## 1. 动作空间全量设计

### 1.1 三维抽象 (最终形态)

动作 = (verb, target, param)

| 维 | 含义 | 取值范围 | 网络输出 |
|----|------|---------|---------|
| verb | 动作类型 | 0-31 (32 种) | logits[32] |
| target | 目标实体槽 | 0-7 (obs 实体槽: 英雄/城镇/对象) | logits[8] |
| param | 数量/档位 | 0-3 (4 档) | logits[4] |

实现: PPO 输出 3 个 head, loss = 3×CE 之和。**v1 用冻结 Discrete 码表过渡**(见 1.2), v2 切 MultiDiscrete 三维——码表结构保持兼容, 只是编码方式不同。

### 1.3 target 语义 (obs 实体槽)

target 从 obs 的实体槽取 (与 heroes/towns 段索引一致):

| 槽 | v1 (简化) | v2 (精细化, obs 已预留) |
|----|-----------|------------------------|
| 0-7 | 英雄槽: 最近的友方英雄自动映射 | 显式: obs[target_list] 里的英雄索引 |
| 城镇 | 最近己方城镇自动映射 | 显式: obs[target_list] 里的城镇索引 |
| 对象 | MOVE_TO 用 obs 标记的最近对象 | 显式: obs[target_list] 里的对象索引 |

v1 引擎侧做"最近目标"解析, v2 用预留的 target_list obs 段 (见 2.2 段9)。
