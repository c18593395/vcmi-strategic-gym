# 方案: own_town 重复访问衰减 (A3 备料, 只写不部署)

日期: 2026-09-17 | 状态: 📝 备料 (等批次A 窗口结束后按晋级纪律排期)
前置: P10 scorer 已灰度 (`--target_chain scorer`), 本方案是其增量, 默认参数 0 = 零行为

## §0 现象与证据

- 单局 `[SCORE] pick=... type=own_town score=89.5` 霸屏 589 行, 模型反复回城空撞 (走回城→取兵窗无产出→目标重选又选城→再走回城)。
- 89.5 的出处 (打分公式硬推导, target_scorer.py L289-295):
  - own_town: `V=35` (L56), `delta_cap=0` (L269), `power_c=0 → F=+1.0` (L272), `p_phase=0` (L283)
  - `score = 1.0×35 + 0 + 1.0×(35+20) − 0.5×g + 2.0×stick = 90 − 0.5g + 2×stick`
  - 贴脸 g=1, 无 stick → **89.5**; g=5 → 87.5。即: **own_town 在 25 格内恒定 85-90 分, 无任何衰减项**, 天然碾压矿 (V=30 → score≈80−0.5g) 与资源堆。
- 对照: 蓝英雄贴脸可达分 (V=100, delta=1.0): `100+150+F×120−0.5g` ≈ 300+, 真目标不需要让位; 问题只在 own_town 与**资源/守卫类中价值目标**之间。

## §1 根因 (三件套叠加)

1. **V 常数无衰减**: `OWN_TOWN_VALUE=35.0` 每次打分恒定, 第 5 次回城和第 1 次同分。#232 远目标衰减 (L264-267) 只覆盖蓝英雄/蓝城, own_town 不在列。
2. **取兵窗无效果校验**: ep_runner L583-596 visit 窗触发只看 `recruit_mask≠0` (位域=引擎解锁), **不看 gold 是否够/巢穴是否有货** → mask 有位但招不了 → 4 步 RECRUIT 空转, 兵力零增量, 纯烧步 (T04 的 res_ok 检查 L516-519 只在动作采样侧, scorer 候选 4 无钱检查)。
3. **stick 破坏后回流**: stall≥6 时 stick=0 (L274-276), 重选时 own_town 仍以 87-90 分重新夺回头名 → 空撞循环闭环。

## §2 方案: 衰减曲线 + 空撞拉黑 (A+B 组合)

### A. 按访问次数指数衰减 V (主刀)

runner 维护本局 `{town_id: visit_count}`, scorer 候选 4 打分时:

```python
# target_scorer.py type_value() 内, c 增加 "own_visits" 字段 (runner 传入)
if c.get("is_own_town"):
    v = OWN_TOWN_VALUE
    _dec = c.get("own_town_decay", 0.0)   # 0=关闭 (默认零行为)
    if _dec > 0:
        v = v * (0.5 ** min(int(c.get("own_visits", 0)), 3))  # 35 → 17.5 → 8.75 → 4.4 封底
    return v
```

- 衰减后分数对照 (g=1): visits=0 → 90 (合法首访不受影响) / 1 → 55 / 2 → 37.5 / 3 → 28.75
- 接管验证: 矿 g=10 → 75 > visits=1 的 55 ✓; 守卫 g=8 (V=45): 45+65−4=106 恒压 own_town ✓
- 每 3 次封底, 保留"走投无路回城"兜底 (资源全清时仍可选, 只是不再霸屏)

### B. 空撞拉黑 (精准补刀)

visit 取兵窗结束 (visit_econ_steps 归零) 时检查兵力增量:

```python
# ep_runner_one.py visit 窗结束处 (L614 附近状态机)
# 窗开始时快照 econ_prev_army_power, 结束时未变 → 空撞
if _visit_army_snap is not None and _visit_army_now <= _visit_army_snap:
    town_blocked.add(_visited_town_id)   # 本局拉黑, 复用现有 town_blocked 机制
    print(f"[TOWN_EMPTY] town={_visited_town_id} at step {...} (recruit empty, blocked this ep)")
```

- 复用 town_blocked: scorer 蓝城已有同款整类剔除先例 (L189-190), own_town 候选 4 加同款判断即可
- 真取到兵 (增量>0) 不拉黑, 只计数 → 合法取兵成长完全不受影响

## §4 判据与回退

- 生效确认: 主日志/ep 明细 grep `[TOWN_EMPTY]` + `[SCORE] type=own_town` 行数 (基线 589 → 目标 <100/局)
- 行为判据: own_town 平均访问次数下降但 visit 取兵成功率 (有兵力增量的窗占比) 不降
- 安全判据: avg_r 不跌 >20%; 回退 = env 不注入 (默认 0) 或改回 `HOMM3_OWN_TOWN_DECAY` 删除
- 晋级纪律: 批次A 窗收口 → 批次B → 本方案, 一次一轴, 不与 WIN-1 并窗

## §5 防 hacking 自查

- 衰减只降 V 上限, 无新增正奖励源 → 无刷分面
- 每局 visits 重置 → 跨局无累积状态, checkpoint resume 幂等
- 空撞拉黑只影响 scorer 候选排序, 不改 obs/动作掩码 → 模型仍可自主选方向去城 (损失的是引导倾向, 非硬禁)
