### H.4 敌方可见性验证 ✅ (2026-08-14)

**根因确认**: `CGameInfoCallback::getHeroes()` 第 686 行有 `isVisibleFor(hero, *getPlayerID())` 过滤 — AI 侧 callback 带 red 视角, 视野外的敌方英雄不返回。obs 结构有 8 槽位但 fill 只拿到己方 → "战略感知受限"真相。

**修复**: fill_strategic_state 的 players/heroes/towns 三段改从 `gicb->gameState()` 全知直读 (遍历 gs.players), 绕过 callback 可见性过滤。训练期全知视角, 部署期用 isVisibleFor 掩码 (见部署映射设计.md)。

**验证** (collect_bc.py, For Sale.h3m 3玩家):
- players: 3 玩家全可见 (red gold=4050 / blue gold=11000 / tan gold=10900, alive 全 1)
- heroes: 3 玩家英雄全可见 (敌方 owner=1 id=222 pos=(31,23) army=[20]; owner=2 id=223 pos=(3,32) army=[20,7])
- towns: 敌方城镇可见 (owner=2 id=448 pos=(4,31))
- 8 pairs 采集稳定无崩溃

**踩坑** (本次最大教训):
1. **临时验证脚本 (h4_dump_visible.py/h4_verify_v3.py) 会崩, 生产工具 collect_bc.py 一直正常** — 排查 2 小时以为是 .so 问题, 实际是脚本与环境的兼容问题。验证一律用 collect_bc.py
2. **strategic_state.h 改动会连带重编 MLClient.cpp/AIGateway.cpp** (都 include 该头) — MLClient.cpp 里有 `new StrategicState()` + `sizeof(StrategicState)`, 不重编会按旧结构分配 → 堆越界写 → 崩。改头文件后必须强制重编所有依赖 (`rm -f *.o` + rebuild)
3. **8-2 fill_strategic_state 里根本没有 towns 段** (towns 只在 strategic_state_update) — 采集路径 towns 一直是空, 本次补上全知填充
4. g_rl_action / adventure_cb_trampoline / adventure_get_action / register_adventure_delegate 曾丢失 (重写文件时) → 必须保留
5. fill 主体加 shared_lock 后, 内部 fill_exploration/fill_mines/fill_v3_fields 不能再各自加锁 (shared_mutex 非递归, 同线程重复加锁死锁)
