### I.2 C++ BFS 全图寻路 🔄 训练验证中

**代码已完成** (commit 3464c79):
- C++ fill_next_dir(): 全图 BFS 搜索 8 个 target_list 目标
- passability: isLand() + isPassable() + !blocked() (引擎 canMoveFrom 对齐)
- 目标格豁免 blocked 检查 (矿/资源物体让 blocked=true 但可走)
- hero pos: visitablePos() 替代 anchor pos
- z-level 过滤: 跳过不同层 target
- reserved[0..7]=next_dir[8], reserved[8..15]=diagnostics
- Python: obs builder 读 16 槽, ep_runner 三层回退 (C++ BFS → Python 15x15 → 贪心)
- .so 同步 4 处 (rel/bin, build/bin, workspace/vcmi/rel/bin, vcmi-native-build/rel/bin)

**冒烟验证**: 18/18 = 100% BFS 命中率

**训练验证** (KL 调参链):
- KL=0.08 (Phase I.1 最终): klc 触顶 10, avg_r -1.0~-1.6
- KL=0.15 (续训 71 ep): klc 仍触顶 10 占 80%+, 正奖励率 27% (19/71), 最高 r=+74
- KL=0.30 (全新启动, 从 BC 模型): 进行中

**关键发现**:
- 好 ep 特征: 纯方向探索 (无 24 强制), 动作多样 (1,3,4,5,7 混用), r>0
- 差 ep 特征: 6,2 循环 或 END_TURN 投机
- 核心矛盾: BFS 提供好信号, 但 KL 约束太紧锁死学习
- 决策: 全新启动 KL=0.30 从 BC 模型, 释放策略自由度

**下一步**:
- 等 KL=0.30 训练 30+ episodes, 对比 KL=0.15 的指标
- 如果 klc 仍触顶 >50%, 考虑 KL=0.50 或 KL_COEF_MAX 调整
- 如果正奖励率提升, 继续跑 100+ episodes 看趋势
