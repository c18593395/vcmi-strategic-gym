## 🔴 #45: 观测填充（当前阻塞点）

### 已知事实

| 发现 | 详情 |
|------|------|
| `fill_state_from_cb` 从未执行 | `fprintf("FILL: enter")` 未出现在日志。函数加了 stdout 诊断，如果被执行一定能看到 |
| `getHeroesInfo()` 也读 CGameState | `gameState().getPlayerState(*getPlayerID())->getHeroes()` — 跟 igic->gameState() 同源 |
| moveHero 能成功 | 因为它发网络包到服务器，不读客户端 CGameState |
| 旧 .so 进程残留 | 多次 `pkill` 后仍有进程持有旧文件句柄，新 .so 不被加载 |
| `memset(passable,1,32)` 错误 | 设的是每字节=1，int32_t 值=0x01010101=16843009，作为 NN 输入炸裂 |

### 验证方法

`fill_state_from_cb` 函数入口有 `fprintf(stdout, "FILL: enter\n"); fflush(stdout);`。
因为 stdout 被重定向到 `train_loop.log`，只要函数被执行，`grep "FILL" train_loop.log` 就会命中。

### 回退方案（如果 #45 短期修不了）

恢复旧的 `passable[d]=1` 暴力替身 + `strategic_state_update(&igic->gameState())` 调用。
即使 obs 全零，passable 全 1 能让模型探索。之前的 5000+ ep 就是用这个模式跑的。
