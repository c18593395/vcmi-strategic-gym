# 源码分析地图 — VCMI 动作空间与 OBS 设计依据

> 日期: 2026-08-14
> 目的: 从 VCMI fork 源码枚举"动作全集"与"状态全集", 作为动作空间设计/OBS schema 的封闭依据, 防止训练中途发现缺动作/缺状态导致返工。
> 源码根: D:\Bigdata\hero3_fresh\vcmi (smanolloff fork tip)
> 原则: 动作空间 = CCallback 公开方法(封闭列表), OBS = CGameInfoCallback + CGameState/CMap 可读状态(封闭列表)。NK2 是完整动作执行器, 所有接口都有现成调用参照。

| `endTurn()` | 结束回合 | ✅ |

## 面3: NK2 高层动作库 — Behaviors + Goals ✅

目录: `AI/Nullkiller2/Behaviors/` (11 个), `AI/Nullkiller2/Goals/` (15 个)

NK2 是完整 AI, 它拆解出的行为 = 高层动作的现成设计模板:

### Behaviors (行为优先级)
`StartupBehavior` → `RecruitHeroBehavior` → `GatherArmyBehavior` → `BuyArmyBehavior` → `BuildingBehavior` → `CaptureObjectsBehavior` → `ExplorationBehavior` → `DefenceBehavior` → `EscapeBehavior` → `ClusterBehavior` → `StayAtTownBehavior`

### Goals (具体目标)
`CaptureObject` / `ExploreNeighbourTile` / `BuyArmy` / `BuildThis` / `RecruitHero` / `ExecuteHeroChain`(英雄链) / `ExchangeSwapTownHeroes`(换兵) / `AdventureSpellCast`(冒险魔法) / `DigAtTile`(挖宝) / `BuildBoat` / `Trade` / `DismissHero` / `SaveResources` / `StayAtTown` / `CompleteQuest`

**结论**: 每个高层动作都有 NK2 实现可抄。我们的"高层动作"设计 = 选这些 Goal 子集 + 挂到动作码上。

## 面7: 战斗系统 — BattleResult ✅ (本轮新增)

文件: `server/battles/BattleResultProcessor.h/.cpp`, `lib/constants/Enumerations.h`

### BattleResult 关键字段(server 侧)
- `result`: EBattleResult { NORMAL=0, ESCAPE=1, SURRENDER=2 }
- `casualties[side][creatureId]`: 每方每兵种伤亡数
- `battleID` / `queryID` / `victor` / `loser`

### 已有钩子
`ServerPlugin::endBattleHook(BattleResult* br, heroAttacker, heroDefender)` — 已写 g_battle_result (0/1/2/3=无/赢/输/平)

### 战前评估
`getGuardingCreatures(pos)` + `getAIValue()` → 可预估战斗胜负

**结论**: 战斗结果信息完整(胜负+详细伤亡)。当前只用了胜负, 伤亡明细(casualties)可作强化奖励细化。
