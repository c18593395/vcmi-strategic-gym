# HoMM3 战略层 — 卡点与难点清单

## 一、🔴 VCMI 冒险地图 API 暴露（最大卡点）

**问题**：VCMI 的 MMAI 接口目前只暴露了战斗状态（`IState`, `getAction`）。冒险地图状态（英雄位置、城镇、资源、地图对象）的 C++ 类没有 pybind11 绑定。

**需要做的事**：
- 找到 VCMI 中代表"完整游戏状态"的 C++ 类（`CGameState` / `CPlayerState` / `CMap`）
- 用 pybind11 包装关键字段暴露到 Python
- 如果字段太多逐一绑定太慢 → 可以考虑序列化成 JSON 一次性传回，Python 侧解析

**风险**：如果 VCMI 源码改动太大破坏现有战斗 pipe，可能回不去了。

**缓解**：先 fork 一份 VCMI，在副本上改。战斗 pipe 不动。

---

## 二、🔴 动作执行的回合同步

**问题**：自对弈需要红蓝交替操作。VCMI 是事件驱动的——AI 的 `getAction()` 被 VCMI 内部循环调用。如何让两个 AI 在同一个人机交互循环里轮流操作？

**现状**：当前战斗 connector 的 `getAction(side)` 已经支持红蓝双路。但冒险地图上：
- 一个玩家可能有多英雄，需要选"当前英雄"→移动→交互→下一英雄→结束回合
- 英雄移动是**逐格的**（点一下走一格），不是"直接飞到目的地"
- 路径可能有障碍、有敌方英雄挡路、移动力不够走不到

**缓解**：先简化为"英雄只走 8 方向一格"，让 AI 学逐格移动。后续再加路劲规划。

---

## 三、🔴 自对弈中"你在看谁的视角"

**问题**：自对弈时两个 AI 都在同一局里。每个 AI 只能读自己可见的信息，不能读对手隐藏信息（那等于作弊）。

**VCMI 能做吗**：VCMI 内部有"战争迷雾"机制。玩家只能看到视野内的地图。但 MMAI 接口可能暴露了全部信息——需要确认能不能按玩家过滤。

**缓解**：训练阶段先不管，让两个 AI 都读全图（加速训练）。部署/评估阶段再加可见性掩码。

---

## 四、🟡 奖励函数设计（经验：PPO 负奖励 + KL 早停）

**问题（已有坑）**：`h3_env.py 完整成品版` 里记录了——奖励全是惩罚、没有正向鼓励 → ep_rew_mean 持续负 → PPO KL 早停 → 训练崩。

**需要**：
- 密集正向奖励：每走一格 +0.01、每占一个矿 +5、每捡一个宝 +3
- 阶段性目标奖励：首次占矿、首次进城、首次招兵
- Q 键摆烂重罚：`-5`（不是 -2），而且**不结束回合**——让 AI 被迫做点别的
- 动作多样性：连续 5 次同一动作给惩罚

**难点**：奖励 scale 要对——战略局很长（几百步），单步奖励太小学不到，太大梯度爆炸。

---

## 五、🟡 训练收敛速度

**问题**：战斗 5 万步（~10 分钟）就收敛。战略一局可能要几百步，操作空间大得多。

**对比**：

| | 战斗 | 战略 |
|---|---|---|
| 单局步数 | ~4-20 | ~200-500 |
| 动作数 | 2312 | ~20 |
| 观测维 | 28114 | ~200 |
| 收敛需局数 | ~200 局 | ~2000 局+ |

**缓解**：
- 阶段 1：空图（无怪无对手），只学移动+捡资源+结束回合 → 快速建立基线
- 阶段 2：加矿+弱野怪 → 学占矿+简单战斗
- 阶段 3：加 1 个对手 → 学对峙+攻城
- 每阶段跑 500-1000 局

---

## 六、🟡 VCMI 单实例限制

**问题**：当前 VCMI 一个进程只能跑一个战斗。完整游戏也是——一局一个 VCMI 实例。

**自对弈的含义**：红蓝在同一局里交替操作，不需要两个 VCMI 实例。这是一个好消息——不需要解决多实例问题。

**但评估时要**：评估需要当前模型 vs 基线模型打多局。这个要么用 subprocess 隔离（和现在 eval_worker 一样），要么用服务器并行。

---

## 七、🟡 英雄 AI 的"多英雄管理"

**问题**：战略 AI 需要管理多个英雄。一周 7 天，可能有 1-4 个英雄同时活动。每个英雄有自己的移动力、兵力、位置。

**需要决策**：
- 主英雄去打怪/攻城，副英雄去捡资源——但 AI 怎么自动分工？
- 什么时候回城招兵？
- 什么时候把兵从副英雄转给主英雄（英雄链）？

**缓解**：先单英雄训练（AI 只有一个英雄），学会基础移动+占矿+战斗。多英雄是进阶功能。

---

## 八、🟢 终端条件检测

**问题**：怎么判断一局结束？

**VCMI 可以**：游戏状态里有"胜利/失败"标志。还有一个玩家失去所有城镇和英雄 → 淘汰。

**简单处理**：
- 红方失去所有城镇+英雄 → 蓝方赢
- 达到最大回合数（比如 7×4=28 天）→ 比较双方城镇数，多者胜

---

## 九、🟢 地图选择

**问题**：什么地图训？

**建议**：
- 阶段 1-2：自己画的简单地图（36×36，1 城 1 英雄，少量矿和资源）
- 阶段 3：VCMI 自带的随机地图生成器
- 最终：用 `mapgen_4096.py` 生成大量训练图

**关键**：地图要足够多（>50 张），否则 AI 记住特定地图布局而不是学会策略。

---

## 十、优先级排序

| 优先级 | 卡点 | 如果不解决会怎样 |
|--------|------|------------------|
| P0 | VCMI 冒险地图 API | **什么都干不了** |
| P0 | 回合同步+动作执行 | 无法操控游戏 |
| P1 | 奖励函数 | 训练不收敛 |
| P1 | 训练收敛速度 | 训了等于没训 |
| P2 | 可见性过滤 | 训出的 AI 会作弊 |
| P2 | 战斗接入 | 先用自动战斗顶着 |
| P3 | 多英雄管理 | 先单英雄 |

**P0 是硬卡点，先攻克这个**：把 VCMI 冒险地图的 C++ 状态暴露到 Python。搞定了这个，剩下的全是已有经验的 RL 工程。
