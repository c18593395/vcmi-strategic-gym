# 地形栅格数据格式设计 (21x21x4)

> 版本: v1.0 | 日期: 2026-08-23 | 关联: Phase I.4 训练地图体系, CNN 地形编码器

---

## 1. 总览

以英雄为中心的 21x21 局部视野, 4 通道, 用于 CNN 学习空间模式。

```
数据量: 21 x 21 x 4 = 1764 uint8 = 1,764 字节 (~1.7KB)
视野: 英雄周围 10 格 (上下左右各 10)
覆盖: 36x36 地图 56%, 72x72 地图 29%
存储: 独立输入通道 (不走 reserved, 不影响现有 obs)
内存布局: HWC 行优先 (C++ 输出) -> CHW (Python 转置后喂 CNN)
```

## 2. 坐标系

```
grid[r][c] 对应地图坐标:
  map_x = hero_x + (c - 10)   c=0 -> x-10, c=10 -> x, c=20 -> x+10
  map_y = hero_y + (r - 10)   r=0 -> y-10, r=10 -> y, r=20 -> y+10

z 层: 仅取英雄当前所在 z 层, 不做层间混合
边界: 超出地图范围的格子: C0=0, C1=1(不可通行), C2=0, C3=0
```

## 3. 数据类型

```
C++ 侧: uint8_t terrain_grid[1764]  // 独立字段, 不混入 int32 reserved
Python 侧: np.uint8 -> reshape(21,21,4) -> transpose(2,0,1) -> float32 / 255.0
```

- 所有通道值域 0~255, 用 uint8 存储
- C++ 填充时不做浮点缩放, 直接存枚举值
- Python 网络入口处统一 /255.0 归一化

## 4. 内存布局: HWC 行优先

```
C++ 填充顺序: grid[r][c][channel]
  线性索引: idx = (r * 21 + c) * 4 + channel
  
Python 读取:
  raw = np.array(state.terrain_grid[:1764], dtype=np.uint8)      # (1764,)
  hwc = raw.reshape(21, 21, 4)                                    # (21,21,4)
  chw = hwc.transpose(2, 0, 1).astype(np.float32) / 255.0       # (4,21,21)
```

**这是高频踩坑点, 必须写死 HWC, Python transpose 到 CHW.**

## 5. 通道定义

### C0: 地形类型 (terrain_type)

| 值 | 地形 | 可走 |
|----|------|------|
| 0 | 越界/未知 | N |
| 1 | 草地 (grass) | Y |
| 2 | 泥地 (dirt) | Y |
| 3 | 砂地 (sand) | Y |
| 4 | 碎石 (rough) | Y (消耗高) |
| 5 | 道路 (road) | Y (消耗低) |
| 6 | 水 (water) | N |
| 7 | 岩浆 (lava) | N |
| 8 | 雪地 (snow) | Y |
| 9 | 沼泽 (swamp) | Y (消耗高) |
| 10 | 沙漠 (desert) | Y |
| 11 | 岩石面 (rock) | N |
| 12 | 地下 (subterra) | Y |
| 13 | 暗草地 (dark_grass) | Y |

编码: 直接用 VCMI ETerrainType 枚举值 (0~13), 归一化 /13.0 或 /255.0

### C1: 障碍物 (blocked)

| 值 | 说明 |
|----|------|
| 0 | 可通行 (无阻挡物) |
| 1 | 不可通行 (山/树/岩石/建筑/越界) |

### C2: 对象类型 (object_type)

| 值 | 对象 | 说明 |
|----|------|------|
| 0 | 空 | 无可交互对象 |
| 1 | 矿 (mine) | 金矿/锯木厂/铁矿/稀有矿 |
| 2 | 城镇 (town) | 己方/敌方城镇 |
| 3 | 资源 (resource) | 地面资源 |
| 4 | 宝箱 (treasure_chest) | 经验/金币 |
| 5 | 怪物 (monster) | 野怪守卫 |
| 6 | 英雄 (hero) | 己方/敌方英雄 |
| 7 | 宝物 (artifact) | 装备 |
| 8 | 建筑 (dwelling) | 生物招募点 |
| 9 | 传送门 (teleport) | 传送门/入口 |
| 10 | 其他 | 其他可交互对象 |

**同格多对象优先级 (高覆盖低):**
己方/敌方英雄 > 城镇 > 野怪 > 宝物/宝箱 > 资源堆 > 矿场 > 招募建筑 > 传送门 > 其他

### C3: 可见性 (visibility)

| 值 | 说明 |
|----|------|
| 0 | 未探索 (fog of war) |
| 1 | 已探索 (可见) |

训练期全填 1, 部署期用 fogOfWarMap.

## 6. 越界处理

```
当 map_x < 0 || map_x >= W || map_y < 0 || map_y >= H 时:
  C0 = 0   (未知地形)
  C1 = 1   (不可通行, 强制! 防止 CNN 把越界当空地)
  C2 = 0   (无对象)
  C3 = 0   (不可见)
```

## 7. C++ 实现: fill_terrain_grid()

```cpp
// strategic_state.h 新增:
#define GRID_SIZE 21
#define GRID_CHANNELS 4
#define GRID_TOTAL (GRID_SIZE * GRID_SIZE * GRID_CHANNELS)  // 1764

struct StrategicState {
    // ... 现有字段 (int32_t) ...
    int32_t reserved[RESERVED_SIZE];           // 134 (现有)
    uint8_t terrain_grid[GRID_TOTAL];          // 1764 (新增, uint8)
};
```

```cpp
// strategic_state.cpp 新增:
#include "mapObjects/CGMine.h"
#include "mapObjects/CGTownInstance.h"
#include "mapObjects/CGResource.h"
#include "mapObjects/CGCreature.h"
#include "mapObjects/CGHeroInstance.h"
#include "mapObjects/CGArtifact.h"
#include "mapObjects/CGDwelling.h"
#include "mapObjects/CGTeleport.h"

static void fill_terrain_grid(StrategicState* state, CGameInfoCallback* gicb) {
    auto& gs = gicb->gameState();
    auto& map = gs.getMap();

    int ah = state->active_hero;
    if (ah < 0 || ah >= MAX_HEROES || state->heroes[ah].id < 0) return;

    const CGHeroInstance* hero = dynamic_cast<const CGHeroInstance*>(
        gs.getObjInstance(ObjectInstanceID(state->heroes[ah].id)));
    if (!hero) return;

    int3 hpos = hero->visitablePos();
    int hx = hpos.x, hy = hpos.y, hz = hpos.z;
    int W = state->map_width, H = state->map_height;
    int half = GRID_SIZE / 2;  // 10

    for (int r = 0; r < GRID_SIZE; r++) {
        for (int c = 0; c < GRID_SIZE; c++) {
            int mx = hx + (c - half);
            int my = hy + (r - half);
            int idx = (r * GRID_SIZE + c) * GRID_CHANNELS;

            // 越界: C1=1 (不可通行), 其余 0
            if (mx < 0 || mx >= W || my < 0 || my >= H) {
                state->terrain_grid[idx + 0] = 0;
                state->terrain_grid[idx + 1] = 1;  // 不可通行!
                state->terrain_grid[idx + 2] = 0;
                state->terrain_grid[idx + 3] = 0;
                continue;
            }

            auto& tile = map.getTile(int3(mx, my, hz));

            // C0: terrain type
            state->terrain_grid[idx + 0] = (uint8_t)tile.terrainType;

            // C1: blocked
            state->terrain_grid[idx + 1] = tile.blocked() ? 1 : 0;

            // C2: object type (优先级: 高覆盖低)
            uint8_t obj_type = 0;
            for (auto objId : tile.visitableObjects) {
                auto obj = gs.getObjInstance(objId);
                if (!obj) continue;
                uint8_t t = 10;  // 其他
                if (dynamic_cast<CGHeroInstance*>(obj)) t = 6;
                else if (dynamic_cast<CGTownInstance*>(obj)) t = 2;
                else if (dynamic_cast<CGCreature*>(obj)) t = 5;
                else if (dynamic_cast<CGArtifact*>(obj)) t = 7;
                else if (dynamic_cast<CGResource*>(obj)) t = 3;
                else if (dynamic_cast<CGMine*>(obj)) t = 1;
                else if (dynamic_cast<CGDwelling*>(obj)) t = 8;
                else if (dynamic_cast<CGTeleport*>(obj)) t = 9;
                // 优先级: 数字越小优先级越高 (6>2>5>7>3>1>8>9>10)
                // 但我们的编码不是按优先级排的, 用显式比较:
                // hero(6) > town(2) > monster(5) > artifact(7) > resource(3) > mine(1) > dwelling(8) > teleport(9) > other(10)
                // 需要优先级表:
                static const int priority[] = {
                    /* 0=empty */ 99,
                    /* 1=mine */ 5,
                    /* 2=town */ 8,
                    /* 3=resource */ 4,
                    /* 4=chest */ 4,
                    /* 5=monster */ 7,
                    /* 6=hero */ 10,
                    /* 7=artifact */ 6,
                    /* 8=dwelling */ 3,
                    /* 9=teleport */ 2,
                    /* 10=other */ 1,
                };
                if (t < 11 && (obj_type == 0 || priority[t] > priority[obj_type]))
                    obj_type = t;
            }
            state->terrain_grid[idx + 2] = obj_type;

            // C3: visibility (训练期全可见)
            state->terrain_grid[idx + 3] = 1;
        }
    }
}
```

## 9. CNN 编码器架构

```python
class TerrainCNN(nn.Module):
    """21x21x4 地形栅格 -> 128 维特征向量"""
    def __init__(self):
        super().__init__()
        self.conv = nn.Sequential(
            nn.Conv2d(4, 32, 3, padding=1),   # 21x21x32
            nn.ReLU(),
            nn.MaxPool2d(2),                    # 10x10x32
            nn.Conv2d(32, 64, 3, padding=1),   # 10x10x64
            nn.ReLU(),
            nn.MaxPool2d(2),                    # 5x5x64
            nn.Conv2d(64, 128, 3, padding=1),  # 5x5x128
            nn.ReLU(),
            nn.AdaptiveAvgPool2d(1),            # 1x1x128
        )
        self.fc = nn.Linear(128, 128)

    def forward(self, x):
        # x: (batch, 4, 21, 21) float32
        x = self.conv(x)
        x = x.view(x.size(0), -1)
        return self.fc(x)           # (batch, 128)
```

## 10. Net() 集成 (方案2: 独立通道)

```python
class Net(nn.Module):
    def __init__(self):
        super().__init__()
        self.main_branch = nn.Sequential(
            nn.Linear(3464, 256), nn.ReLU(),
            nn.Linear(256, 128), nn.ReLU(),
        )
        self.terrain_cnn = TerrainCNN()
        self.actor = nn.Linear(128 + 128, 25)
        self.critic = nn.Linear(128 + 128, 1)

    def forward(self, obs_main, obs_terrain=None):
        feat_main = self.main_branch(obs_main)
        if obs_terrain is not None:
            feat_terrain = self.terrain_cnn(obs_terrain)
            feat = torch.cat([feat_main, feat_terrain], dim=1)
        else:
            feat = torch.cat([feat_main, torch.zeros_like(feat_main)], dim=1)
        return self.actor(feat), self.critic(feat)
```

## 11. 冒烟测试用例

### Case 1: 基础对齐

```
英雄站在 (10, 10), 右侧格 (11, 10) 是岩石
验证:
  grid[10][11][0] == 11   (rock terrain)
  grid[10][11][1] == 1    (blocked)
  grid[10][10][0] != 0    (hero 格有地形)
  grid[10][10][2] == 6    (hero 自身对象)
```

### Case 2: 边界

```
英雄站在 (0, 0) (地图左上角)
验证:
  grid[0][0][0] != 0      (英雄格有地形)
  grid[0][0][1] == 0      (英雄格可通行)
  对于 r < 10 或 c < 10 的越界格:
    grid[r][c][1] == 1    (越界 = 不可通行)
    grid[r][c][0] == 0    (越界 = 未知地形)
    grid[r][c][2] == 0    (越界 = 无对象)
    grid[r][c][3] == 0    (越界 = 不可见)
```
