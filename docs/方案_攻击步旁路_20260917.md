## §0 背景与根因（A2 定谳，本方案直接依据）

批次B 窗 15 局：9 个非 duel 局无一拍 d≤2（final_min_d 14~96），`BHERO_CONTACT`/`BHERO_KILL`/`TOWN_CAPTURE` 全 0。
三假设终审：

| 假设 | 结论 | 证据 |
|------|------|------|
| ① 蓝英雄 MMAI_RANDOM 漂移 | **排除** | 72_01 贴脸局：蓝英雄 (5,66) step28→68 共 40 拍坐标恒定；plen 68→56 全是红方接近 |
| ② P-H2 接战判据过严 | 曾成立、已修（#250） | 判据修复后仍 0 → 非瓶颈 |
| ③ 战斗没触发 | **结构性根因（本方案对象）** | 见下方证据链 |

**引擎侧证据链（只读核查，零修改）**：
1. `CGameHandler::moveHero`（`server/CGameHandler.cpp` ~L857，mtime 08-29 未变）：STANDARD 路径对"敌方英雄格"走
   `blockingVisit()` → `doMove(BLOCKING_VISIT, VISIT_DEST)` → `objectVisited` →
   `CGHeroInstance::onHeroVisit`（`lib/mapObjects/CGHeroInstance.cpp` L551）：
   `if(ENEMIES){ if(getVisitedTown()) town->onHeroVisit(...); else gameEvents.startBattle(h, this); }`
   —— **对敌方英雄无条件 startBattle，无 aggression 开关**。OBS-3 旧描述"aggression 遗留"方向证伪。
2. `AI/MMAI/AAI/AAI.cpp` L745-758：C++ 侧 0-7 动作执行 `cb->moveHero(h[hidx], target, false)`（transit=false，
   无 isClear 自拦截）—— **C++ 0-7 通道畅通**，战斗可触发。
3. 真正的堵点在 **Python 侧两处**：
   - **堵点一**：`ep_runner_one.py` L493-496，`logits[:8][~passable] = -inf`。passable mask（ML 侧
     `strategic_state.cpp` L680-704 用 `tt->isClear()` 构建）对含敌方英雄的格**必为 0** → 贴脸时朝敌方向
     在 logits 里被置 -inf，模型采不到。
   - **堵点二**：`ep_runner_one.py` L983-985，MOVE_TO 贪心回退只走 `pas[d]==1` 的方向；蓝英雄格 pas=0，
     没有像守卫那样的"pas=0 也强制进入"特判（守卫特判在 L969-981）。

**结论**：在"贴脸（d≤2）且目标=蓝英雄"时，Python 侧既无法让模型采到朝敌方向（堵点一），
也无法让贪心回退走进蓝英雄格（堵点二）→ 战斗永不触发 → `BHERO_KILL`/`TOWN_CAPTURE` 结构性恒 0。
P-H2 接战奖因此"必要不充分"：贴脸奖发了，但真实战斗打不起来。

> 部署前先做单局手动冒烟（§6）。

## §1 设计目标

在 Python 侧（**零 C++ 重编、零 .so 改动、OBS 3464 维度不变、动作空间不变**）打通"贴脸接战"链路：
当满足"目标=蓝英雄 且 已 d≤2 且 战力 logistic F 达标"时，**绕过 passable 屏蔽，强制下发朝敌格的方向码
（0-7）**，使 C++ `moveHero` 落到蓝英雄格 → 引擎 `onHeroVisit` 无条件 `startBattle` → R6 战斗 AI 结算。

## §2 机制（复用守卫特判同族模式）

守卫特判（L969-981）是已有先例：守卫格 pas=0，但通过 `move_guard_target` 标记 + "pas[d] 或 move_guard_target"
的特判，允许**绕过 passable 检查强制进入守卫格触发战斗**。本方案把同一族模式扩到"蓝英雄目标"：

**触发链（仅当 `--blue_hero_attack_bypass=1` 时生效，默认 0 零行为变化）**：
1. 目标选择（legacy 链 / scorer 链任一）选出 `move_target` = 某蓝英雄 `(bx,by,bz)`。
2. 在 MOVE_TO 执行段（L936 `if tx is not None`）：
   - 计算 `d = |tx-hx| + |ty-hy|`（曼哈顿，与 P-H2 口径一致）。
   - 若 `is_blue_hero_target`（目标来源 = 蓝英雄 obs 段 / scorer `is_blue_hero` 候选）且 `d <= contact_d`（复用
     `--blue_hero_contact_d`，批次B=2）→ **进入攻击步分支**：
     - **战力护栏**：计算 logistic `F = 2σ((log1p(power_self) − log1p(power_blue) − margin)/temp) − 1`
       （与 `target_scorer.power_feasibility` 同公式）。`power_self` 读 `obs[base+10]`（active hero total_power），
       `power_blue` 读蓝英雄槽 `obs[128+bh*26+10]`。**仅当 `F >= attack_f_min`（默认 0.0，即"打得过"才进）才下发**；
       打不过 → 不下发（保持原守卫式绕行/贪心行为，不送死）。
     - **方向码**：取 `tx,ty` 相对 `hx,hy` 的主方向（贪心 cand 同序：先主方向后次方向），挑那个"下一格==蓝英雄格"
       的 d；若 d<=2 且同格/8邻，直接取朝蓝英雄的那一个方向码（与守卫 L973-977 同写法）。
     - **绕过 passable**：对该方向**不检查** `pas[d]`（守卫 L980 `pas[d] or move_guard_target` 的"或"同款，
       本方案对蓝英雄目标也加 `or move_blue_hero_target`），直接 `a = d`。
3. `env.step(a)` 下发 0-7 → C++ `moveHero(target, false)` → 落到蓝英雄格 → `startBattle` → R6 结算。
   战斗胜负/奖励走既有管道（`BHERO_KILL` 阶梯 / `TOWN_CAPTURE` proxy / 守卫式 `+100`），**零新增奖励逻辑**。

**幂等（每敌一次）**：复用 `_contact_paid`（P-H2 已建）。攻击步只对"尚未接战"的蓝英雄下发；一旦
`_contact_paid` 命中该 id，后续不再强攻该 id（避免打完后还去撞尸）。
- 实际上"打完后蓝英雄 id 从 obs 消失"（BHERO_KILL 双帧确认），自然不再候选 → 幂等由既有机制保证；
  `_attack_tried` 集合作双保险，记录本局已下发过攻击步的蓝英雄 id，避免同 id 反复强攻（瞬态空拍回读时防振荡）。

**送死兜底**：
- 战力 F 护栏 = "打不过就不进"（`attack_f_min` 默认 0，可调高更保守）。
- 真送死由既有 `death_penalty`（默认 -50）/ `battle_result` 失败信号（`reward_battle_mult` 只奖 red 赢）兜底，
  模型学到"强攻 → 输 → 负奖励"自然收敛（不新增硬兜底，避免过度设计）。

## §3 参数（argparse，全部默认 0/关，零行为变化）

| 参数 | 类型 | 默认 | 含义 |
|------|------|------|------|
| `--blue_hero_attack_bypass` | int | 0 | 总开关：1=启用蓝英雄攻击步旁路（贴脸强攻），0=关闭（零行为） |
| `--attack_f_min` | float | 0.0 | 战力 logistic F 阈值：≥ 此值才下发（"打得过"才进；默认 0.0 = 战力对等即可） |

**部署方式（零干扰）**：与批次B 同款——systemd 启动参数注入，**不改代码默认值**；
`--blue_hero_attack_bypass` 默认 0，开窗时只加 `--blue_hero_attack_bypass=1`（+ 可选 `--attack_f_min`），
关窗即摘参数，行为 100% 回退旧代码。

## §4 代码改动点（ep_runner_one.py，Python 零重编）

1. **argparse（L150 后，`--kill_r_next` 之后）**：新增 `--blue_hero_attack_bypass`（int, 0）+ `--attack_f_min`（float, 0.0）。
2. **状态初始化（L407 后，`guard_done_countdown` 附近）**：
   - `move_blue_hero_target = False`（本拍目标=蓝英雄，攻击步分支标记，同族 `move_guard_target`）。
   - `blue_hero_id_target = None`（目标蓝英雄 id，幂等 + F 读战力用）。
   - `_attack_tried = set()`（本局已下发攻击步的蓝英雄 id，幂等双保险）。
3. **目标选择侧**：
   - legacy 链：当目标来源为蓝英雄时（当前无此分支——蓝英雄不进 legacy 目标池，只进 scorer 池）。
     见 §4.4 统一处理：**只在 scorer 候选层识别 `is_blue_hero`**，legacy 保持零改动（最小面）。
   - scorer 链（L758-775）：`_pick["is_blue_hero"]` 为 True 时，设 `move_blue_hero_target = True`、
     `blue_hero_id_target = 该蓝英雄 id`（候选 dict 需带回 id，见 §4.4 target_scorer 改动）。
4. **MOVE_TO 执行段（L936 `if tx is not None` 内）**：在现有守卫分支（L971-982）**同位置并列**加蓝英雄分支：
   - `if move_blue_hero_target and d <= contact_d and F >= attack_f_min and blue_hero_id_target not in _attack_tried:`
     - 取朝蓝英雄格的方向码（贪心 cand 中 `next==(tx,ty)` 的那个，或 d≤2 直接取主方向）。
     - **不检查 pas[d]**（绕过堵点一/二）：`a = d`。
     - `_attack_tried.add(blue_hero_id_target)`。
     - 打 `[BHERO_ATTACK]` 埋点（同族 `[GUARD]` 打印 + 旁路 `BHERO_EV_LOG`）：
       `map / blue_hero_id / step / d / F / power_self / power_blue / dir=d`，供批次B 窗聚合"接战是否真的触发"。
   - 否则 → 保持既有行为（不进入）。
5. **堵点一协同（可选，最小面下不强制）**：攻击步分支已直接 `a=d` 绕过贪心 passable 检查，
   堵点一（logits mask）只影响"模型自采样 0-7"，不影响"贪心/攻击步直接定 a"——**攻击步分支不走采样**，
   直接定动作码，因此堵点一无需改（保持采样侧对蓝英雄方向仍屏蔽 = 防模型乱撞；只允许引导层强攻）。
   这是**引导层旁路**而非采样层放开，符合"复用守卫特判同族模式"拍板。

## §6 部署前冒烟（用户拍板，必须先行）

**目标**：72_01（`T06_72_01`）单局，红英雄贴到蓝英雄相邻（d≤1）后，**手动下发一次朝蓝英雄的攻击步**，

1. `CBattleQuery` 弹出（引擎侧 `startBattle` 真发生，非静默拒绝）——看 ep 日志 `[BHERO_ATTACK]` +
   VCMI server 侧 `BattleProcessor::startBattle` 行。
2. R6 战斗 AI 结算（onnxruntime BAI 链路）：`battle_result` 翻转（`state.battle_result` 0→1/2/3）+
   无 `Router battleStart exception ... fallback to StupidAI`（R6 已修，应零 fallback）。
3. 蓝英雄若被歼 → `BHERO_KILL`/`TOWN_CAPTURE` proxy 发奖（链路闭合）。

**方法（零干扰，不碰 systemd 训练进程）**：
- 写**只读冒烟脚本** `py/a2_attack_smoke.py`：读 72_01 的 `objects.json`（蓝英雄出生坐标）+ 红英雄出生坐标，
  断言初始 d 关系；**实机验证**走 `ep_runner_one.py` 单局手动跑（`--move_to_force` 短 + 临时
  `--blue_hero_attack_bypass=1`），观察 `[BHERO_ATTACK]` 埋点 + 战斗行。**单局**（`max_turns` 小）不占用
  训练主窗，跑完即弃，不写 checkpoint。
- 冒烟通过判据：日志出现 `[BHERO_ATTACK] dir=X` 且**随后**出现 `BattleProcessor::startBattle` /
  `battle_result` 非 0 行。若引擎静默拒绝（"destination tile is blocked!"）→ 证明旁路不通，回查堵点，
  **不部署**。
