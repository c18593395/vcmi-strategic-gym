> 日期: 2026-09-11
> 来源: 源码逆向 (`lib/serializer/`, `lib/network/`, `lib/networkPacks/`)
> 用途: T13 外挂 AI 客户端协议实现参考

## 1. TCP 帧格式

```
┌─────────────────────┬──────────────────────┐
│  Header (4 bytes)   │  Payload (N bytes)    │
│  uint32 = N         │  CPack 序列化数据     │
└─────────────────────┴──────────────────────┘
```

- **Header**: 4 字节 uint32，little-endian，表示 payload 长度
- **Payload**: N 字节，CPack 的二进制序列化结果
- **Heartbeat**: header=0, payload 为空（每 10 秒发送一次空包保活）
- **最大包**: 64MB (`messageMaxSize = 64 * 1024 * 1024`)
- **TCP 选项**: `no_delay=true`（禁用 Nagle 算法）

## 2. 二进制序列化规则

### 2.1 标量类型

| C++ 类型 | 序列化格式 | 大小 |
|----------|-----------|------|
| `bool` | 1 byte (0 或 1) | 1 |
| `int8_t` / `uint8_t` | 1 byte 原始值 | 1 |
| `int32_t` / `si32` | 变长整数 (LVarInt) | 1-10 |
| `uint32_t` / `ui32` | 变长整数 (LVarInt, 作为 int32) | 1-10 |
| `float` | 4 bytes IEEE 754 原始 | 4 |
| `double` | 8 bytes IEEE 754 原始 | 8 |
| `Enum` (int32_t 基) | 转 int32_t → 变长整数 | 1-10 |

### 2.2 变长整数编码 (LVarInt)

```
编码 (保存):
  value → uint64 abs
  while value > 0x3f:
    byte = (value & 0x7f) | 0x80
    value >>= 7
  lastByte = value & 0x3f
  if negative: lastByte |= 0x40
  输出: [byte序列] + [lastByte]

解码 (加载):
  offset = 0
  value = 0
  loop:
    byte = read()
    if byte & 0x80:
      value |= (byte & 0x7f) << offset
      offset += 7
    else:
      value |= (byte & 0x3f) << offset
      if byte & 0x40: return -value
      else: return value
```

注意: 所有 ≥2 字节的整数类型都用此编码。1 字节的直接写入原始值。

### 2.3 容器类型

| 类型 | 格式 |
|------|------|
| `std::vector<T>` | `save(uint32_t length)` (变长整数) + 依次 save 每个元素 |
| `boost::small_vector<T,N>` | 同上 |
| `std::set<T>` | `save(uint32_t length)` + 依次 save 每个元素 |
| `std::unordered_set<T>` | `save(uint32_t length)` + 依次 save 每个元素 |
| `std::array<T,N>` | 直接 save 每个元素（无 length 前缀） |
| `std::map<K,V>` | `save(uint32_t length)` + 对每对: save(key) + save(value) |
| `std::unordered_map<K,V>` | 同上 |
| `std::pair<T1,T2>` | save(first) + save(second) |

### 2.4 字符串 `std::string`

**带去重机制**:

```
保存:
  if empty: save(uint32_t(0))
  else if 已保存过: save(int32_t(id))  // id = -1, -2, ...
  else:
    save(uint32_t(length))
    write(raw_bytes)
    记录 string → id 映射 (新 id = -1 - count)

加载:
  load(int32_t length)
  if length < 0: 从已加载列表中取 (-length - 1)
  if length == 0: 空字符串
  if length > 0: 读取 length 字节原始数据
```

### 2.5 指针 `std::shared_ptr<T>` / `std::unique_ptr<T>` / 裸指针

```
保存:
  save(bool isNull)
  if isNull: return
  if 已保存过: save(uint32_t pointerID)
  else:
    save(uint32_t pointerID)  // 从 0 递增
    save(uint16_t typeID)     // CTypeList 注册 ID
    if typeID == 0: 直接调用 data->serialize()
    else: 调用注册的 SerializerReflection::savePtr()

加载:
  load(bool isNull)
  if isNull: return
  load(uint32_t pointerID)
  if 已加载过: 直接取引用
  load(uint16_t typeID)
  根据 typeID 创建对象 + 调用 serialize()
```

**指针追踪**: `trackSerializedPointers = true`，同一个对象多次出现只序列化一次。

### 2.6 `std::optional<T>`

```
保存:
  if has_value: save(uint8_t(1)) + save(*value)
  else: save(uint32_t(0))

加载:
  load(uint8_t present)
  if present: load(T) → make_optional
  else: 空 optional
```

### 2.7 `std::variant<T0, T1, ...>`

```
保存:
  save(int32_t index)  // 哪个 alternative
  save(对应 alternative)

加载:
  load(int32_t index)
  load(对应 alternative)
```

### 2.8 `std::bitset<N>` (N ≤ 64)

```
保存:
  N ≤ 16: save(uint16_t)
  N ≤ 32: save(uint32_t)
  N ≤ 64: save(uint64_t)

加载: 对应类型 load() → 转 bitset
```

### 2.9 `int3` (地图坐标)

```cpp
class int3 {
    si32 x, y, z;
    serialize: h & x; h & y; h & z;  // 三个变长整数
};
```

### 2.10 标识符类型

| 类型 | 序列化方式 | 说明 |
|------|-----------|------|
| `StaticIdentifier<T>` (ObjectInstanceID, QueryID, BattleID, PlayerColor, SlotID, TeamID) | `h & num` → int32 变长整数 | 直接序列化 int32 值 |
| `EntityIdentifier<T>` (HeroTypeID, HeroClassID, CreatureID, BuildingID, SpellID, ArtifactID) | `h & encode(num)` → std::string | 编码为字符串再序列化 |
| `StaticIdentifierWithEnum<T>` (EPathfindingLayer, EArmyFormation, EMarketMode) | `h & num` → int32 变长整数 | 同 StaticIdentifier |

### 4.2 CPackForServer 序列化

每个服务器包的序列化格式统一:

```
[isNull(1 byte)]
[pointerID(变长整数)]
[typeID(2 bytes)]    ← 180=EndTurn, 182=MoveHero, 197=QueryReply, ...
[player(变长整数)]   ← PlayerColor::num
[requestID(变长整数)]
[... 子类特定字段 ...]
```

## 5. 核心包字节布局详解

### 5.1 EndTurn (TypeID=180)

```
序列化: CPackForServer → (无额外字段)

字节布局:
  1 byte  : isNull = 0x00
  ~1-2 bytes : pointerID (0)
  2 bytes : typeID = 0xB4 0x00 (180)
  ~1-2 bytes : player.num (PlayerColor)
  ~1-2 bytes : requestID (uint32)

总大小: ~6-9 bytes (典型情况)
```

### 5.2 MoveHero (TypeID=182)

```
序列化: CPackForServer + path + layer + hid + transit

字节布局:
  1 byte  : isNull = 0x00
  ~1-2 bytes : pointerID (0)
  2 bytes : typeID = 0xB6 0x00 (182)
  ~1-2 bytes : player.num
  ~1-2 bytes : requestID
  ~1-2 bytes : path.length (uint32, 变长)
  对每个 int3 路径点:
    ~1-2 bytes : x (si32)
    ~1-2 bytes : y (si32)
    ~1-2 bytes : z (si32)
  ~1-2 bytes : layer (EPathfindingLayer, enum→int32)
  ~1-2 bytes : hid.num (ObjectInstanceID)
  1 byte  : transit (bool, 0x00 或 0x01)

典型大小 (1 路径点): ~12-18 bytes
典型大小 (10 路径点): ~40-60 bytes
```

### 5.3 QueryReply (TypeID=197)

```
序列化: CPackForServer + qid + reply(optional<int32>)

字节布局:
  1 byte  : isNull = 0x00
  ~1-2 bytes : pointerID (0)
  2 bytes : typeID = 0xC5 0x00 (197)
  ~1-2 bytes : player.num
  ~1-2 bytes : requestID
  ~1-2 bytes : qid.num (QueryID)
  1 byte  : optional.present (uint8, 0x01=有值, 0x00=无值)
  if present: ~1-2 bytes : reply.value (int32)

典型大小: ~8-12 bytes
```

### 5.4 RecruitCreatures (TypeID=187)

```
序列化: CPackForServer + tid + dst + crid + amount + level

字节布局:
  [CPackForServer 部分同上]
  2 bytes : typeID = 0xBB 0x00 (187)
  ~1-2 bytes : player.num
  ~1-2 bytes : requestID
  ~1-2 bytes : tid.num (ObjectInstanceID, StaticIdentifier)
  ~1-2 bytes : dst.num (ObjectInstanceID, StaticIdentifier)
  [crid 是 CreatureID = EntityIdentifier → std::string]
  ~1-2 bytes : crid string length (int32)
  N bytes  : crid string raw (如 "core:footman")
  ~1-2 bytes : amount (ui32)
  ~1-2 bytes : level (si32)

典型大小: ~25-35 bytes
```

### 5.5 MakeAction (TypeID=198)

```
序列化: CPackForServer + BattleAction ba + BattleID battleID

字节布局:
  [CPackForServer 部分同上]
  2 bytes : typeID = 0xC6 0x00 (198)
  ~1-2 bytes : player.num
  ~1-2 bytes : requestID
  [BattleAction 序列化 — 复杂, 见 §5.6]
  ~1-2 bytes : battleID.num (BattleID, StaticIdentifier)
```

### 5.6 BattleAction 序列化

BattleAction 是战斗层动作，结构复杂:

```cpp
struct BattleAction {
    EActionType type;           // 动作类型 (enum)
    PlayerColor side;           // 行动方
    BattleStackID stackID;      // 堆栈 ID
    int3 tile;                  // 位置
    std::vector<int3> path;     // 路径
    si32 range;                 // 范围
    si32 spellID;               // 法术 ID
    std::vector<std::pair<BattleStackID, si32>> targets;  // 目标列表
    si32 amount;                // 数量
};
```

序列化格式取决于具体字段类型:
- `type`: enum → int32 变长
- `side`: PlayerColor (StaticIdentifier) → int32 变长
- `stackID`: BattleStackID (StaticIdentifier) → int32 变长
- `tile`: int3 → 3×int32 变长
- `path`: vector<int3> → 变长 + 元素
- `spellID`: SpellID (EntityIdentifier) → std::string
- `targets`: vector<pair<BattleStackID, si32>> → 变长 + 元素
- `amount`: si32 → 变长

## 6. 客户端连接流程

### 6.1 建立连接

```
1. TCP 连接到 server:port
2. server 发送欢迎消息 (LobbyClientConnected)
3. 客户端发送加入请求 (LobbySetPlayer 等)
4. server 分配 playerColor, 发送 PlayerStartsTurn (Query)
5. 客户端回复 QueryReply(qid, 0) 确认开始
```

### 6.2 游戏流程

```
server → PlayerStartsTurn (Query)
client → QueryReply(qid, 0)  // "我准备好了"
client → MoveHero(path, layer, hid, false)  // 移动
client → MoveHero(...)  // 继续移动
client → EndTurn()  // 结束回合
server → TryMoveHero(...)  // 移动结果
server → PackageApplied(requestID)  // 包已处理
```

### 6.3 Query 超时

如果 server 发送 Query 类型包而客户端不及时回复 QueryReply，server 会卡死。必须自动回复所有 Query。

## 7. 实现路径建议

### 路径 A: C++ headless client (推荐)

```
1. #include VCMI 头文件 (NetworkConnection, GameConnection, BinarySerializer)
2. 创建 NetworkHandler → connectToRemote()
3. 实现 INetworkClientListener → onPacketReceived() 回调
4. 用 GameConnection::sendPack() 发送 CPackForServer 子类
5. 用 GameConnection::retrievePack() 解析 CPackForClient
```

优点: 直接复用 VCMI 序列化代码，零逆向风险
缺点: 需要 VCMI 构建环境

### 路径 B: Python 外挂

```
1. 实现 LVarInt 编解码
2. 实现所有容器类型的序列化/反序列化
3. 实现指针追踪 (isNull + pid + tid)
4. 实现字符串去重
5. 实现类型 ID → 类映射
```

优点: 独立，不依赖 VCMI
缺点: 工作量大，需完整逆向

### 路径 C: C++ 外挂 (不链接 VCMI)

```
1. 复制序列化逻辑到独立库
2. 只依赖 Boost.Asio (TCP)
3. 手动实现类型 ID 表
```

优点: 独立部署
缺点: 需维护类型 ID 同步
