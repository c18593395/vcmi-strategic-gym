## 一、训练 / 环境踩坑

### 1.1 step2 挂死（已修复）
- **根因**：SEND→WAIT 顺序导致 `s_turn_player` 被提前消费。
- **修复**：改为 WAIT→SEND + 切 Nullkiller2（回调后 fall through，不手动 endTurn）。
- **来源**：历史记录（旧知识库 §四.1）。**状态**：已修复（5 步全通，vloss 769→45）。

### 1.2 MMAI core dump（已绕过）
- **根因**：旧 MLClient 含 broken `g_cached_game_state` 代码。
- **修复**：清理 + 切 Nullkiller2，用 cond_shutdown 版本。
- **来源**：旧 §四.2。**状态**：已绕过。

### 1.3 ABI 不兼容（已修复）
- **根因**：vcmi-native 与 workspace 两套源码混搭 `.so`。
- **修复**：从 vcmi-native 全量重编三件套（libvcmi.so + libmlclient.so + connector）。
- **来源**：旧 §四.3。**状态**：已修复（三件套必须同源编译，见知识库 §三.1）。

### 1.4 .pyc 缓存过期（已修复）
- **根因**：NTFS 文件系统 pyc 过期检测不可靠。
- **修复**：部署后 `find ... -name __pycache__ -exec rm -rf {} +`。
- **来源**：旧 §四.4。**状态**：已修复。

### 1.5 subprocess 僵尸（已修复）
- **根因**：VCMI 线程阻止 Python 退出。
- **修复**：`os._exit(0)` 硬退出。
- **来源**：旧 §四.5。**状态**：已修复。

### 1.6 DummyVecEnv 短路（已修复）
- **根因**：PPO 构造时 DummyVecEnv 调 reset，导致 adventure_wait 阻塞。
- **修复**：reset 加 `_vcmi_just_started` 标志，跳过一次。
- **来源**：旧 §四.6。**状态**：已修复。

### 1.7 子 agent 401（已修复）
- **根因**：`delegation.provider=custom`，硬编码 api_key 过期。
- **修复**：provider 改 deepseek，api_key 留空走 `DEEPSEEK_API_KEY` 环境变量。
- **来源**：旧 §四.7。**状态**：已修复。

### 1.8 用 vmap 跑战略训练（认知已更新）
- **旧记**：战略图误用战斗 vmap，assert 不过 → 结论"只用 H3M"。
- **更正（2026-09-24 源码核实）**：**当前项目战略训练统一用 `.vmap` 冒险地图**（T05/T06/`King_of_Pain_h3m.vmap`），`strategic_env.py` 强制 mapname 含 `adventure` 关键字；H3M 经典图（`available_maps.json` 110 张）是另一套，用于旧 ELO / 经典图评估。
- **来源**：`train_wsl2_ppo_v2.py` L30-95；`maps/training/` 目录（68 个 .vmap）；`strategic_env.py` L491-535。**状态**：旧 §四.8 描述已过时，以本条目为准（详见知识库 §二.5）。

### 1.9 ckpt_push_hook.py global 声明顺序 bug（已修复）
- **根因**：`main()` 内先 `default=SERVER` 引用全局，下方才写 `global SERVER,...`，Python 报 `SyntaxError: name 'SERVER' is used prior to global declaration`。
- **修复**：`global` 上移至 `main()` 顶部、置于任何引用之前；移除非重赋值项；顺带显式 `import urllib.error`（原仅靠 `urllib.request` 传递导入）。
- **来源**：`py/ckpt_push_hook.py`（已修，语法校验通过）。**状态**：已修复。

## 二、服务器 / 链路踩坑

### 2.1 服务器旧架构跑不了新模型（架构约束）
- **根因**：`/DATA/hero3/vcmi-build/bin/*.so` 是 ARM64 编译旧 v13 架构（obs 256 维 / 11 动作）；新模型 3464 维 + 4×21×21 地形 CNN + 25 动作，维度与 ABI 都不兼容。
- **结论**：WIN RATE 评测只能在 WSL2（唯一 x86 带新引擎的机器）算，结果回传 :8088 集中存放；**不要迷信"推到服务器评测"**。
- **来源**：`file` 实测 `*.so` 为 aarch64 + 知识库 §五.2。

### 2.2 本机 sandbox 禁用 wsl.exe（环境坑）
- **根因**：本机 WorkBuddy sandbox 将 `wsl.exe` 列入 Program Blacklist，执行报 `PROGRAM BLOCKED BY SECURITY POLICY`。
- **影响**：任何需在 WSL2 内运行的脚本/命令（含 `wsl -d Ubuntu`、训练、评测）都无法在此环境端到端验证。
- **处置**：只写文件（WSL 经 `/mnt/d/` 可见）交用户/WSL 内实跑；语法校验用 Windows 侧 `python -m py_compile` / `bash -n` 兜底；跨机链路文档标注"未在此环境跑通"。
- **来源**：实测。**状态**：环境限制（非代码 bug）。

### 2.3 :8080 推理延迟口径（实测差异，勿混用）
- **现象**：知识库中"2–12ms"与"20–33ms"两个延迟数字并存，看似矛盾。
- **根因**：两者测的是不同口径——
  - **用户实测 2–12ms**：P8 客户端在**局域网本机**对 `:8080/predict` 的往返（网络跳数少）。
  - **sandbox 实测 20–33ms**：服务器响应自带的 `inference_time_ms` 字段（纯服务端推理耗时）；从本机 sandbox 发起的 wall ≈ 73–165ms 因经容器 NAT 跳数，不代表 LAN 客户端。
- **处置**：写文档时两值都标注来源与口径；精确延迟以你 P8 客户端在局域网本机实测为准，不取 sandbox 的 wall。
- **来源**：`curl :8080/openapi.json` 确认 `PredictionResponse.inference_time_ms` 字段 + 8 次实测采样；用户说明（2026-09-24）。**状态**：已厘清口径（见知识库 §5.2）。

## 三、认知纠正（易错点，均经源码核实）

### 3.1 地图格式：战略训练用 vmap，不是 H3M
- 见 1.8。一句话：当前 PPO 训练图全是 `maps/training/*.vmap`；`available_maps.json` 的 110 张 H3M 是经典图另一套。
- 旧知识库 §3.4 曾写"战略训练只用 H3M"，**与源码相反**，已更正（知识库 §二.5）。

### 3.2 动作 10 = END_TURN，动作 24 = MOVE_TO（勿颠倒）
- 旧知识库曾写成"10=保留、24=结束回合"，与源码相反。
- 正确：`END_TURN = 10`，`MOVE_TO = 24`【来源：strategic_env.py L196, L211】。
- 见知识库 §二.3。

### 3.3 观测 3464 是状态向量，地形是独立输入
- obs **不含** 4×21×21 地形；地形以独立 `(4,21,21)` 栅格传入 CNN 第二输入 `model(obs, terrain)`。
- **来源**：strategic_env.py L235-236；train_wsl2_ppo_v2.py L152 `forward(x, terrain)`。

### 3.4 服务器 :8080 只能评旧 SB3 模型
- 80 个模型全是旧 256 维 SB3；新 3464 维 ONNX 能 load 但 predict 维度不兼容。
- **来源**：curl `:8080/health` 实测（current_model=`ppo_Key to Victory_h3m_500000steps`）。
