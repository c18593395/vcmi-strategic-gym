# 方案 T7.4 — 死亡惩罚设计稿 (2026-09-10, 停训窗口备料)

> 状态: 📋 设计稿, 实装等 capture 观察窗稳定后 (激励轴不同窗纪律)。
> 触发条件: T06 [TOWN_CAPTURE] 观察判据 (触发非零 / avg_r 跌幅<20% / 自发≥80% / 守卫胜≥80%) 达标后的下一窗。

## 1. 问题定量 (为什么修)

| 证据 | 数据 | 后果 |
|------|------|------|
| 首胜-战死关联 | 7/7 局首胜后战死 | "拿完奖励就送死"是稳定剧本 |
| 死亡局 vs 超时局收益 | 死亡 r=+50~+93, 超时 r=-18~-107 | **死比活着结算更赚** (步数惩罚烧穿) |
| capture 联动 | 攻城败 = 英雄死局终 | 送死成本≈0 → capture +100 可被"送死碰运气"套利 |
| 价值学习污染 | vloss 不降 (历史) | 死亡点 GAE bootstrap 异常 |

## 2. 事实链 (代码实锤)

- **引擎判负不可达**: 死亡局 game_over 恒 0 — zombie 现象本身即证明 (英雄死后 yourTurn 仍在调 = 引擎未判 standardDefeat); strategic_env.py L1117 的 `game_over==2 → -200` 存在但**永远轮不到**。
- **ep_runner 死亡路径**: 8 方向 passable 全 0 → zombie_streak>=2 (L1152) → `traj["done"][-1]=True` 提前终局, **无任何奖励调整**。
- **clip**: ±300 (L1122), 死亡罚插入后不会被剪 (事件奖已入, 需保证同帧 |reward|≤300, -50/-100 安全)。

## 3. 方案 (ep_runner 层, 纯 Python, 零 C++ 改动)

**zombie 确认点追加死亡罚** (L1152-1155 块内):

```python
if zombie_streak >= 2:
    traj["rewards"][-1] += args.death_penalty   # 新参数, 默认 -50
    traj["done"][-1] = True
    print(f"[HERO_DEATH] penalty {args.death_penalty}, end ep at step {traj['steps']}", flush=True)
```

实现要点:
- 全局生效 (不按图分支) — 死亡惩罚是一个完整激励轴, T04 无死亡局零扰动, 无需分支。
- `traj["rewards"][-1]` 追加 = 惩罚落在死亡确认帧, GAE 经 done=True 截断 bootstrap, 不污染后续 (无后续)。
- 主日志白名单加 `[HERO_DEATH]` (train_wsl2_ppo_v2.py)。
- 参数 `--death_penalty` argparse 默认 -50, 命令行可调 (支持零停训参数实验与回退)。

## 4. 参数定档 (-50 起步, 上限 -100)

| 档 | 值 | 依据 |
|----|-----|------|
| 试探 | **-50** | 守卫战 +100 / 死亡 -50: 强守卫打赢净 +50 仍正 → 不劝退接战 (T05 守卫战是核心战斗信号源, **过强惩罚 = 避战退化风险**) |
| 加深 | -100 (对称守卫) | 仅当 -50 档送死剧本未消失且接战率不塌 |
| 回退 | 0 (argparse 传 0 即关) | 接战率塌或 avg_r 恶化 |

## 5. 观察判据 (1-2 窗) 与回退线

- ✅ 达标: 死亡局 r 由正转负 / [GUARD] 接战频率不塌 (对比基线 ±20%) / avg_r 跌幅 <20% / 送死止损剧本 (首胜后速死) 消失。
- ❌ 回退: 接战率塌 >30% 或 avg_r 跌 >20% → 降档 -25 或 -0 关闭。

## 6. 边界与遗留
